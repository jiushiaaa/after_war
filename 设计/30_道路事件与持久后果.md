## 1 模块归属与实际接口

| 状态／接口 | 当前职责 |
| --- | --- |
| `CivilIncidents` | 独立随机状态、预警、选择、期限、维修结果、全路自动维护授权、原生事件及只读摘要 |
| `Regions.route.condition` | 只有`open / closed`；不新增blocked枚举 |
| `Regions.setRoute`、`route.enabled` | 控制新货运；旧车继续本趟，忙时保留原两人班组；不控制迁居客运 |
| `Regions.launch` | 一条路线的一辆原车，复用真实货物、费用和班组；先检查事件hold |
| `Regions.repairRoad(s,id,options)` | **唯一维修付款入口**，实扣home木20、工具4；可修closed道路，也可解决该路未结预警 |
| `Regions.returnShipment` | 去程货退home、回程货退地方；按已行路段折返，必要时还要空车回home |
| `Passenger.quote`、Urban旧出发分支 | 检查hold，禁止赴该地方的新批次；不改已出发旅队 |
| `Urban.roadOpen` | 继续仅判断实际通路及河谷道路／外站维护；用于旧旅队行进与返程，不承载hold |
| `History.snapshot` | 只读投影预警、抉择、实际封路和实付修复，不参与结算 |

`CivilIncidents`不另建人口、仓库、车辆、客运装备或施工岗位。来源到目标的120秒迁居任务与home径向货运仍是两种任务；不能把它们称为已经建成的铁路。

## 2 实际候选条件与持久调度

`eligible(s)`要求物流已激活、掌握logistics、节点已发现、路线condition为open，且`Regions.serviceReady(s,id)`成立。后者检查：

- 路线enabled、原班组实际完整、已有`completedTrips > 0`。
- `lastDeliveredAt`或`lastSupplyAt`中最新的实际到货记录，距当前不超过`max(180, travel × 2 + 30)`秒。
- 近期证据可以是贸易返抵，也可以是建设等真实交付；签约、出发、空返和预测不能代替到货。

**没有额外实现`lastDeliveredAt > introducedAt`条件，也没有在候选方法中另做一次河谷外站维护判断。** 后续实际发车仍由Regions原有通路与维护门槛控制。新模块引入后至少600模拟秒才首次尝试，因此旧档不会在初始化时立即触发预警。

全局最多一个未解决道路事件。当前有原生弹窗或`c.pending`时不抽新事件；已存在事件的到期、排空仍继续检查。道路提示在继任、探索、政制、地方／城市职责、共同预算和城市群议题之后，在旧冷风随机事件之前展示。

调度规则已经固定：

1. 首次`nextRollAt = introducedAt + 600`。到达调度时间且允许新事件时，先把下一次检查设为当时elapsed＋600。
2. 无候选时不推进随机数。有候选时按routeId排序，只抽一次；小于0.5生成预警，并用同一次抽值在候选中选路，否则本次无事件。
3. 生成后下一次检查至少为`createdAt + 1800`；解决后进一步延至至少`resolvedAt + 1800`。已有未结事件时不生成第二条。
4. 关窗、换届、读档不会重置这些字段；修复会明确延长为修复后至少1800秒。被其他弹窗占用时，尝试可以晚于计划时间，不补抽离线期间的轮次。

随机递推为32位LCG：`rng = (1664525 × rng + 1013904223) mod 2^32`。初始seed由introducedAt确定且避免零seed，后续rng允许全部uint32值。`rolls`记录真实抽取次数。渲染、报价、历史、保存、解码和init不推进随机状态；旧冷风／兽足的`Math.random`尚未改造成这套持久调度。

## 3 原生选择及期限

初始`warning`没有封路倒计时，不扣费、不立即阻路。

| 原生选择 | 已实现结果 |
| --- | --- |
| 加固修复（木20工具4） | 一次实付后解决本次预警，道路保持／恢复open，旧车位置和remaining不重置 |
| 修复并授权各路自动维护 | 本次实付成功后设全局`autoRoads=true`；失败不会获得授权 |
| 继续运输（180秒后封路） | `choice='watch'`、`phase='watch'`，点击时记chosenAt，dueAt严格为chosenAt＋180 |
| 停新发车，旧车归来后封路 | `choice='hold'`、`phase='holding'`；只阻该路新货车及目标为该地的新批次迁居 |
| 先去准备材料 | warning保持不变，记为已提示；没有隐藏倒计时，之后可从地区入口再打开 |

watch选定后不再提供改选hold的按钮，只能等待或付费修复。holding可随时付费解除。closed阶段关闭窗口也不会免费开路。

`record.offered`使警报可读后暂放：选择备料、失败维修提示及其他仍活跃的原生选择会确认该提示，`nextEvent`不再每秒自动弹回。`choose`底层调用失败仍然零写；原生事件层单独负责提示确认。新记录显式`offered:false`；旧记录缺字段按未提示解释，init不补写，因此已经导出的自然57仍可逐字保持。

## 4 hold排空与封路时序

`holds(s,id)`仅作为新出发门槛，接在`Regions.launch`、`Passenger.quote`及Urban未加载Passenger时的旧路径。当前Urban正式出发同步重新取得报价再付款，不保存可跨事件继续提交的旧报价。hold不修改enabled、assigned、已出发目标、成员、装备、住房预留或remaining。

排空只看真实队列：

```js
!regions.shipments.some(p => p.route === id) &&
!urban.parties.some(p => p.target === id)
```

所有phase／state均算未归来：载货、候装、empty、refitting、已安置居民后的空返、年更死亡后名册为空的车组，以及尚未回到原来源的返乡旅队。不能根据货物为空、人口已admitted或assigned为零提前封路。source名字相近而target为home的旅队不属于这条径向地方道路。

**实际钩子在每秒Regions／Urban owner tick之前运行。** 若最后一辆车在本秒owner执行时归来并移出队列，事件通常在下一模拟秒检查到空队列后封路；不是本秒owner尾部立即封路。自然首例即102998秒回货、102999秒封路。watch到期同样在当秒运输推进前关路。`lastTickAt`防止同一时刻重复推进。

原车仍可交货、从地方实扣返货或完成原路撤回；原旅队可正常安置再空返。若地方缺备货或客运缺完整班组，holding可能持续等待，必须通过原调岗、备货、撤回或付费修复解决，不能删队列或免费释放装备。当前摘要显示等待归来，尚未新增逐车排空计数界面。

## 5 closed后的守恒与真实代价

closed直接沿用现有运输机制：

- 正常outbound、inbound、empty货车停止，货物留在原车；`returning`可沿已走路段退回出资仓，不能穿越断路向前瞬移。
- 去程撤回只退未交付cargo，不退旅粮、木材或装备维护；回程货物退回地方仓后，同一空车仍须等修路才能回home。
- 地方候装撤回成为空返；已交付药、工具和工程材料不退。公共工程、市政、公用服务、货车改装、共同预算继续由各owner核对材料和回执。
- 地方旅队按Urban原规则受阻、消耗预付旅粮、等待或原路返乡。途中年龄、死亡、来源床位及Origins回执继续正常结算；事件不改名册。
- `returnShipment`会主动将该货运路线enabled置false；维修只开道路，不替玩家重新启运、不补退休工人。原本enabled的计划则按原班组和合同继续。

Finance不会因道路事件自动暂停或撤约：协调知识费继续实付，未按期回货仍记录本期欠供，暂停约定仍走既有公示规则。Regions的出口预算按原启用计划保持保守预留，不因hold凭空增加可花储备。行政整合、地方供养和Metro由各模块检查实际状态；事件不直接扣信任、伪造履约或删除历史城市／条约。

## 6 唯一维修事务与全路自动维护

实际入口为：

```js
CivilRegions.repairRoad(s, routeId, {
  incidentId,             // 事件按钮绑定原ID；旧地区入口可省略
  mode: 'manual' | 'auto'
})
```

它先核对道路、可修阶段、可选incidentId与mode；自动模式还要求已授权且当前为warning；然后一次`CivilRules.pay(s,{wood:20,tools:4})`，再恢复condition=open并由`CivilIncidents.recordRepair`记录结果、清activeId和延后冷却。`recordRepair`是成功付款后的内部记账步骤，不是另一个免费维修按钮。

事件按钮、旧地区维修按钮与自动维护都走上述唯一入口。原生按钮只显示费用，不另附`cost`让Events再扣一份。不足任一材料、旧事件ID或已解决记录都失败零扣；原生提示依据实际布尔结果，不再固定写“已经修通”。没有事件记录的合法旧closed道路仍可原价修复，不凭空补造预警与历史付款。

`autoRoads`是**所有路线共用的常设授权**，不是按路线保存的开关。授权必须通过一次成功的“修复并授权各路自动维护”；取消授权只影响未来，不退款、不改变既有事件。

每次新预警生成时，若已授权，立即尝试一次同样的实付维修：足额则记`payment.mode='auto'`并写左侧记录，本次预警自动解决，不弹出待处理窗口；缺料则保留warning并请玩家决定，不启动watch，也不每秒偷偷重试。自动模式不能替玩家修复已经选定的watch、holding或closed事件。后续可手动修复这次问题，常设授权本身仍保留。

本片沿用即时道路维修抽象，没有新增维修岗位、施工时间、载具修理或桥梁工程。

## 7 实际保存结构与校验

模块新增于`c.incidents`，没有独立`content/incidents.js`：

```js
{
  schema: 1, introducedAt, rng, rolls: 0,
  nextRollAt, lastTickAt: null, nextId: 1,
  activeId: null, autoRoads: false, records: []
}
```

每条记录的实际字段为：

```js
{
  id, type: 'road_warning', route, createdAt,
  cause: {completedTrips, lastDeliveredAt},
  phase: 'warning',             // warning / watch / holding / closed / resolved
  choice: null,                // null / watch / hold
  chosenAt: null, dueAt: null, closedAt: null,
  resolvedAt: null, outcome: null, // 解决后为prevented或repaired
  payment: null,                // {at, cost:{wood:20,tools:4}, mode:'manual'|'auto'}
  offered: false                // 兼容旧记录缺失，不主动补写
}
```

校验已覆盖唯一活跃记录、递增ID、地点存在、原因快照、阶段／选择时间、watch严格180秒、付款恒定值、一次结果和pending引用。`closed`必须对应当前closed道路；已经resolved的历史不要求这条路以后永远开放。实际已花掉库存、人物换届或车辆返家，不会使历史付款失效。

随机状态通过`seed(introducedAt)`与rolls推导核对；采用仿射LCG快速推进，复杂度为**O(log rolls)**，不在每次读档重放多年tick。`lastTickAt=null`只允许空初始账；下一抽取时间不得退到最近生成／解决记录的1800秒冷却之前。篡改rng、丢弃调度时刻、回退冷却及非法offered值均有拒绝回归。

合法旧档缺模块时只加空账和一次初始等待，原名册、库存、车辆、道路condition及预算逐字保留；显式null、坏schema或坏类型拒绝。二次init幂等，导入不推进生产、运输、倒计时或抽取。保存于截止瞬间但尚待真实tick执行的合法状态不因到期而被拒绝，也不补算现实离线时间。

当前没有新增Regions的roadIncidentId反删引用。pending为roadIncident而缺模块会拒绝；若外部删除整个事件账且没有pending痕迹，单凭旧版也允许的closed道路不能判它必定损坏。这一边界未冒充已实现的防删审计。

## 8 原生入口与发展史

地区页`#regionsPanel`在有事件历史后出现“查看道路预警”和当前摘要；未发现、未发生的事件不先堆占位按钮。旧地方详情保留同一付费维修入口，不另开地点或管理面板。

warning说明尚未计时，watch显示实际剩余秒数，holding说明等待旧车与旅队归来，closed说明付费恢复。全路自动维护状态、取消授权和备料后重开均在原生事件内。当前提供固定20／4费用和失败原因，不声称已新增逐资源缺额计算或每车排空列表。

`c.pending`只负责当前展示；阶段保存在事件record，done清pending不会丢失后果。只读发展史用`road_warning_ID / road_choice_ID / road_closed_ID / road_repair_ID`四种键展示实际发生的阶段；预防性修复没有虚构的封路条目。历史视图不扣费、不清事件、不改道路、不推进PRNG。
