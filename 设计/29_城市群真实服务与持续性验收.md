# 城市群真实服务与持续性验收

2026 年 11 月 1 日。本文件补充设计26第6、7节，依据本轮实际 `Metro / Services / Urban / Municipal / Industry / Regions / Finance / adapter` 代码。**Metro 第二片已经实现，23项专项与集成回归以及自然下载53的旧档迁移验证已经完成；自然三城3000与城市群登记仍未达成。** 本文记录当前实装规则。Metro只拥有观察样本、稳定段和历史登记，不复制人口、库存、电力或Finance的权威账。

设计26第一片的共同预算和真实货运已经实现。第二片继续采用 home 加当前同一协议的两个地方成员、各城当前至少400居民、合计至少3000居民，以及600模拟秒持续检查。来源留守人口、在途旅客、累计迁入、未参加协议的第四节点不计入3000。

## 1 实际生产边界，以及观察应在何时发生

权威时间是 `civilization.elapsed`，生产由 `civilization.productionClock` 每累计10秒触发。**不能假定生产发生在 `elapsed % 10 === 0`**。生产时钟可以因已有事件重新定相，存档也保存其余数。

当前 `Civilization.settleEconomy(s)` 的实付顺序为 Rules → Village → Society → Industry → Regions（含 Municipal）→ Origins → Finance → Urban → Finance.observe → **Metro.observe**。Metro在生产尾观察并保留这轮实际得到服务的名册；随后同一秒的主tick才处理迁入、衰老、货车到达、地方建设和旅队到达。Finance先关期、Regions后处理同秒返抵；Finance.receive已支持在 `returnedAt === period.endsAt` 时更新该期缺项，真正迟到不追改截止时的缺项。

当前采用生产尾 `observe`、owner ticks尾 `finalize` 的两阶段接线。只有observe已完成所有非预算检查、且本次失败项全部为budget时，才把该轮at、协议和原稳定段存进以State为键的 `pendingFinal` WeakMap。finalize仅在同秒、同协议下复核预算；若原车恰好按期返抵使唯一的预算缺口消失，就恢复该次观察本应得到的稳定结果。它不重跑生产、不采第二份样本，也不额外增加第二个10秒。WeakMap是瞬态运行数据，不入存档，reset会清空；不能跨秒或靠读档补做这次恢复。

同秒稍后的出生、退休、死亡或旅队抵达可能改变名册。纯 `check` 比较当前名册摘要与最后一个真实生产样本；不一致时显示“等待下一轮供养核验”并阻止登记，但不清除刚刚真实观察过的稳定段。下一轮observe再按那轮实际居民、住房、治疗与其他服务继续检查。预算补核也不会给新增居民补造上一轮服务。`refresh / check / event` 不补跑结算；克隆预测不能反写真实观察或冒充已经发生的治疗、供水、工业生产。

## 2 Services：实际用过的水与下一轮新水证不是同一个字段

现有字段的准确含义如下：

| 字段／接口 | 当前含义 | Metro 用途 |
| --- | --- | --- |
| `services.nodes[id].irrigation = {at, waterCapacity}` | `begin` 在该 at 成功消费旧水证后，留下本轮已兑现服务；本轮无证时记0 | 本轮当地人口的实际供水覆盖证据 |
| `services.nodes[id].economy = {at, waterCapacity, medicine, used, demand}` | 本轮水务和药剂师真正支付材料、分配即时电力后得到的结果 | 证明本轮公用服务运行；这里的供水将用于下一生产轮 |
| `services.nodes[id].water = {issuedAt, usableAt, validUntil, capacity, consumed}` | 本轮 `run` 新发的一张水证；`usableAt = validUntil = issuedAt + 10` | 下一轮预测的输入，不是本轮已经消费的证明 |
| `CivilServices.waterCapacity(s,id)` | 最近10秒公用服务产水量，用于现有建设门槛与展示 | 不足以单独证明本轮已经用水 |
| `CivilServices.nextSettlementAt(s,id)` | 优先选择未来10秒内水证的可用时刻，否则按实际 `productionClock` 推算下个边界 | 克隆预测的标准时刻 |
| `CivilServices.farmRate(s,id)` | 纯读本轮 irrigation；只有已建灌溉改造且本轮水量覆盖当地居民时，新田片为2，否则1.4 | 不能通过重复调用产生或消费额外水 |

**现代码没有 `irrigation.usedAt` 字段。** `begin` 先把旧水证 `consumed` 置真，随后同轮 `run` 会用下一张水证覆盖 `water`，其 `consumed` 又是 false。因此在完整生产结束后要求 `water.consumed === true` 会错误拒绝正常城市；只看 `water.capacity` 则可能把还没用过的新证当成本轮服务。

在实际生产边界 t 的供水硬条件为：存在该地 Services 节点，`irrigation.at === t`，其 `waterCapacity >= 当前当地居民数`；同时该地公用服务 `economy.at === t`，发电与使用仍满足本地所有者的约束。不能用 home 的水证给地方城抵数，也不能把两城各200人份相加填满一座400人城。

水量已经由真实材料、岗位和电力产生：电动每站4个实际水务工、4电、0.2化学品、0.02零件，供600人份；手动每站8个实际水务工、同样材料、0电，供300人份。观察器读取实付结果，不再扣材料、不重乘手动倍率、不二次消费旧证。`begin` 同 at 重复调用返回0，但保留该 at 已有 irrigation 证据；Metro 无需也不得为了核验再调用它。

缺化学品或电力时，前轮已付的水可以合法支撑当前一轮，当前 `run` 只发0容量的新证；下一轮必然失去水覆盖。下一轮纯预测可提前显示这个缺口，但不能据此否认已经发生的上一轮付款。

现有 Services.validate 会检查形状、时刻和设施容量，但不会另存已经被覆盖的旧水证付款历史。不能声称仅凭一条旧 irrigation 就能重放证明过去600秒水费；Metro的证明来自连续真实观察，旧档的一条合法记录只能成为一个当前样本。

真实偏移样例来自 `游戏/tests/fixtures/natural-common-freight.json`：elapsed=73944，productionClock=2，home经济 at=73942；irrigation 为73942／1200人份，water 为 issued73942、usable73952、capacity1200、consumed=false。下一生产边界是73952，不是73950或73954。

完整城市资格仍需逐地复核健康≥70、真实治疗与儿童教学、粮药净余量非负、工业链完整、机械生产实际用电≥4、污染<40，以及原有工具40／铁40／零件20底线。公用水泵耗了4电并不等于机械生产用电4；装机、power.demand、历史 online 或电池式累加都不成立。电力限于本地本轮使用，`used <= generation`，不能拿别城余电补足。

在观察边界 t，三个经济对象必须 `e.at === t`。现有 developmentReady 为普通界面容许10秒内的最近证据，Metro 不能仅调用它便给陈旧证据增加新的10秒。城市旗标是历史里程碑，无法替代这些当期检查。

`food / medicine` 的既有余量已经包含一次共同出口承诺：home 的 Urban.settle 在真实总 delta 上加负向 `Regions.committedFlow(s,'home')`；地方 economy 在本地真实 delta 中减去 `Municipal.tradeExports`，该接口已统一读取 Regions。不能再扣一次 Finance 药品、工具、木材。进口从不提前作为本地产量计入。

Finance 的知识协调费由真实 Finance.settle 独占扣除。不能从 `e.food` 推断记录费已经支付；应单独查本期付款凭据。本轮参数没有把财政开支再乘home政体产出倍率，也没有将home倍率传播至地方。

## 4 最近三轮维护与300秒储备

当前 Urban 和 Municipal 只保存**最新一轮**经济记录。Finance 的 `serviceTotals` 是周期累计，不保留逐轮序列；不能将累计量除以次数冒充“最近三轮”，不能读取不存在的 `economy.history`。Metro已经在 `civilization.metro.samples` 保存最多三个真实生产样本，每个样本含at、各成员的census摘要和实付resources。缺旧样本的档必须实际运行三轮形成窗口，不回填历史。

每个样本必须同一成员、同一生产 at，实际间隔10秒；同 at 重复观察不追加。`paidInputs.resources` 是实际 gross 投入，正产出不抵消成本；例如本轮造工具5、用工具3，维护证据仍为3，不是净增长2。治疗和口粮单独记，运输、资本建设、制度记录费用不冒充生产维护。旧档缺少该证据可以合法导入，但在补齐真实轮次前不可通过城市群维护储备检查。

对工具、煤、零件、化学品这四项，按设计26使用：

```
单轮需求[r] = max(最近三个实际生产轮的 paidInputs.resources[r], 下一轮纯预测投入[r])
300秒维护底线[r] = 单轮需求[r] × 30
```

每项分别取最大值，不能先加成“总价值”，不能三轮取平均。缺项在**存在且合法的该轮证据对象中**表示0；整个 paidInputs 缺失不等于0成本。现有城市工具≥40等基础门槛仍同时存在，使用两个底线中较高者，而不是把40再当耗材扣一次。

基本口粮底线可直接用 `CivilUrban.foodReserve(s) * 2.5` 或 `CivilMunicipal.foodReserve(s,id) * 2.5`，从原120秒需求换到300秒。home包含真实分龄、配给与蓄水设施节省；地方按自己的分龄人数与0.12，不套home配给倍率。治疗药品底线为当前居民×0.01×30。地方 `mealInputs` 是付了多少，短缺时会小于需求，不能拿短缺实付量降低下一轮口粮底线。

在上述基础上，当前 `Metro.reserve` 还逐资源加上 `-Regions.committedFlow(s,id)[r] × 30` 的已承诺出口与旅费储备，避免用同一批货同时满足生产和对外支出。距离下次年度更新不超过300秒时，另用真实名册、可用床位和既有出生规则的纯计算，加入该次可能出生所需的粮药；这不提前生人，也不扣款。最后应用工具至少40、铁至少40、零件至少20的既有城市底线。

这些是库存检查，不是再次付款。净供养检查扣一次承诺、库存检查留出未来支出，是两个不同条件；没有重复实际付款。生产耗用、出生、旅费、材料车仍由原owner实付。Finance发货仍保护原120秒底线，不自动为Metro冻结300秒库存；真实支出后纯check可阻止登记，下一真实observe若仍不满足条件则清稳定段。没有第二份公库或可兑物资债权。

下一轮纯预测已有接口，但返回形状不同：

- home：`CivilUrban.forecast(s)` 返回 `copy / flow / deltas / paidInputs / treatmentInputs`。它没有执行 Urban.settle 来刷新 `copy.urban.economy`；下一轮时间取 `result.paidInputs.at`，用电读 `result.copy.civilization.industry`。下一轮粮药余量由 `result.deltas` 加当前统一负出口承诺各一次。
- 地方：`CivilMunicipal.forecast(s,id)` 返回 `food / medicine / education / treatment / productivePower / industry / paidInputs / treatmentInputs / mealInputs / copy`。food、medicine已含统一出口，不再重复减。知识协调费也在克隆中实算，不能将其再扣到真实仓。
- 两者均使用 `CivilServices.nextSettlementAt` 选择真实下一边界。只在深克隆中消费水证、模拟材料与电力；不调用货车发车、年度人口或真实UI事件。Metro.check重复调用前后，整个原 State 必须逐字一致。

## 5 Finance：上一个完整周期与本期连续实付

权威对象是 `civilization.finance.agreements / periods / orders / receipts`。当前合同通过 `CivilFinance.agreement(s)` 取得；应固定使用该合同的成员，不随市政当前选中节点变动。暂停或退出后不允许继续积累城市群稳定时间，但旧在途货物与旧账仍保留。

周期是 `[approvedAt + 600*k, approvedAt + 600*(k+1))`，不是世界整年，也不是生产时钟。要证明上一完整周期，应取**当前同一协议的紧邻前一期 index-1**，而非在历史中挑一个曾成功的周期：

1. 该期确实存在，`endsAt - startedAt === 600` 且 `closedAt === endsAt`。退出而提前关闭的一小段不是完整周期；跳过的周期不会被 Finance 补造。
2. 每个指定地方有该期唯一订单，真实状态complete，返程收入 `returnedAt <= endsAt`；`missed` 为空，并与合法订单／回执一致。出发、只到地方、空车回家或返货均不等于履约。恰好等于截止秒可以通过，晚一秒不可以。
3. 本轮既定实现口径要求60笔真实协调付款，按10秒连续，第一笔在 `[startedAt, startedAt+10)` 内，最后一笔为第一笔+590。每笔mode和costs按自己的当时凭据验证，不要求整期都等于当前改革后的模式。不能只比较paidAdmin总金额，补付一大笔或60笔集中在同一秒都不成立。

首次签约若落在一个已经结算过的生产时刻，第一完整日历段可能只有59笔付款；它不能被补成60笔，也不能用批准费代替。让后面的真实完整周期达到要求。这个明确边界避免以旧系统尚未承担的职责虚构“连续履约”。

本期连续付款也不能仅用 `coordinationReady(s)`：它只证明本期最近10秒内有一次付款。设本次真实经济边界为 t，本期起点为 start，则本轮应检查的生产网格是从 t 每次减10，直到小于start；这给出了本期截至该生产轮的所有应付 at。每个 at 都须有且仅有一张实际付款，最后一张就是t。不能要求 `start + 10*n`，也不能要求付款秒数被10整除。缺一轮、生产节奏出现超过10秒的缺口或尚未到首个真实边界，都不能通过伪造付款弥补。

真实存档的例子：协议 approvedAt=73018；上一期 `[73018,73618)` 的付款为73022、73032、…、73612，共60笔。本期 `[73618,74218)` 在经济 at=73942 时应有73622、73632、…、73942，共33笔。elapsed=73944的界面刷新不再增加第34笔。

跨周期恰在两次生产之间的几秒，不能把“新一期尚未到第一生产轮”误写成已经欠付。纯展示按最近真实经济 at 判断哪些付款已到期；只有实际下一生产边界才推进观察。Finance的累计 serviceTotals可供展示真实累计治疗与投入，但不证明三轮水覆盖，也不能单独证明600秒完整服务。

## 6 600秒稳定：61个合格边界，缺口不补计

首次收齐三轮样本并通过全部条件的生产边界 t0，只建立起点，稳定秒数为0。t0+10是10秒，t0+590是590秒；第61个连续合格生产边界t0+600才为600秒。不能第一次通过就加10，不能用60个观察点宣称已经经过600秒。

同一个 at 的第二次 observe、界面刷新、纯check、forecast和读档初始化都不增加稳定度，也不再次追加维护样本。后一个观察at必须恰比前一个大10，才累加10；出现缺口时从新的合格边界重新计0，而不是 `min(delta,10)` 继续接上，更不能一次补出几百秒。

真实observe时，人口／住房／供养／水证／教学／工业／维护库存／通路／班组／当前行政服务／预算付款等条件失效，会清本次稳定段；同秒按期回车的budget-only误拒按第1节补核。纯check在观察后的名册变化或其他当前缺口上只阻止登记，不修改真实已观察段。已登记城市、财产、条约和城市群历史formedAt不会因后来断供被删除。退出后清当前观察；新协议和新成员从零起段，不能挪用旧协议的稳定时间，原formedAgreementId与formedMembers仍保留。

存档只续接已经真实观察过的序列。正常在 t0+3 保存、以原elapsed读回，下一生产发生在t0+10，允许接着累计，因为游戏内只又走了7秒；玩家关闭页面的现实时间不算。若导入状态中elapsed已跨越未观察的间隔，首次新观察必须重新起段，绝不按elapsed差补跑稳定度或伪造维护记录。缺Metro字段的合法旧档不能由旧Finance累计和city旗标直接推导出600秒。

纯检查在两个生产边界之间可以显示最近结果和当前新缺口，但不制造观察。事件排队后点击时应再次检查当前人口、仓库、协议、道路和最近证据，确认600秒合格段仍有效；失败只说明当前缺口，不写“城市群成立”成功记录。

## 7 已实现的渐进原生入口与API

继续使用议事屋和既有Events，不新增财政页、城市群dashboard或第九标签。Finance保留“查看共同约定”。当前共同协议已有任意一个地方成员登记city，也就是home之外出现第二城市时，议事屋就显示 `#metroButton`“核对三城职责”和 `#metroSummary`。第三城、3000人或其他服务尚缺时，显示实际人数、进度和具体缺口，不要求先达成城市群才看得到目标。已经登记过的城市群即使后来退出协议，历史入口仍保留。

按钮不抢现有Events或pending事件；当前可以登记时打开 `metroCharter`，否则打开 `metroStatus`。首次达标可自动提出一次议题；选择“继续核对账册”或处理登记按钮后写 `offered=true`，不反复自动弹出。玩家仍可通过同一手动按钮复核或重新申请登记。

`canRegister` 要求尚未登记、稳定满600秒、当前check仍通过、四轴已成立，并且没有待继任、正在改制或Finance修订公示。`register`只写 `formedAt / formedAgreementId / formedMembers / formedStableSince`；按钮点击时再次核验，失败使用失败文案，不假报成立。没有人口、科技、库存、国家或永久产出奖励。取得实际同意前不称建国，历史旗标也不等于已有国家财政或统一主权。

当前API已接线：

- `init / validate / reset`：缺模块的合法旧档只初始化空观察；显式坏对象、非法时间或引用拒绝。reset仅清WeakMap瞬态。存在Metro pending而缺模块不能当旧档放过。
- `check / canRegister`：纯读当前三地、费用、样本与克隆预测，返回具体缺口或登记资格，不改原仓库和观察时间。
- `observe / finalize`：按第1节分别拥有生产观察和限定的同秒预算补核。
- `previousFulfilled / coordinated / financeCheck`：复核现有Finance付款、订单、回执及生产偏移，没有另一套财政历史。
- `reserve / birthReserve / forecastReady`：只计算储备与下一轮可行性，不生产、不征调、不发车、不出生。
- `nextEvent / event / refresh / register`：原生渐进入口、一次自动提示和明确的登记事务。

持久观察字段位于 `civilization.metro`，包含schema1、introducedAt、当前agreementId与members、最多三份samples、lastObservedAt、stableSince与stableSeconds、四个formed历史字段，以及offered。Services仍直接读取实际irrigation，Finance仍使用真实periods/orders/receipts；没有新增 `water.usedAt`、`economy.lastThree` 或 `Finance.complete=true` 等替代凭证。

## 8 最小验收矩阵与目前证据边界

| 回归 | 必须得到的结果 |
