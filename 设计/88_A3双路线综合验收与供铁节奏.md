# 88 · A3 双路线综合验收与供铁节奏

本轮继续设计74的阶段关口：以工业273和独立公共214两条世界验收城市群，限定在现有城市经营、贸易、公共责任及失误恢复。不增加第六座同质城市或新型外交菜单。最终数字、存档和浏览器证据见 `验证/双路线综合验收_验收.md`。

## 1. 收口问题与结论口径

A3的目标是“多城分工有取舍，两条经营路线能接入；不要求每城重复建齐所有设施”。本轮检查三个问题：

1. 工业路线的标准加工能否通过真实供铁持续运行，而非每次缺料手动点击援助。
2. 公共路线能否用原有农业、医疗、木构资产进入三城、安居、代际接班和机构治理，而非补做一遍工业前置。
3. 机构接管后需要多少介入，故障能否解释、撤回和恢复，历史账目增长是否继续拖慢阅读与加载。

自然验收的身份是已有两份独立新档的延伸。不是重新从砍柴完整游玩一次，也不是新玩家盲测。构造适配器二十年与真实UI十年窗口分列；不能用它们宣布12—15小时总流程已达标。

## 2. 湖滨供铁：从库存波动定位到吞吐约束

原“工料协作”每批最多24铁、160工具，往返至少360秒。即使车不停，本线供铁也只有每10秒0.667铁；湖滨标准加工的实际需求更高。因此反复在修造与标准间切换不是多等一会便能解决。

新“工序补库”是一次明确签署的新协约，持久化为 `contract/mode: restock`，不是修改旧 `industry` 的费率或历史货物：

- 湖滨先拥有实付标准加工章程，本城已有机械传动与标准计量；旧约结束、原车归仓后，双方各实付12知识签署。
- 每批最多240铁、40工具；对向仍最多1400粮、80废料，实物等值交换。实际数额由真实库存、需求、整数折值、载重决定，常低于上限。
- 湖滨铁目标600；出发仓本地备料目标300、出口至少留60。目标只是生产/采购的停止线，不产生库存。
- 现有技术工优先承担冶炼：要求量为 `ceil(240 / 36 / 0.3) = 23`，受现有炉位和合格技术人数一半限制；原有更大的冶炼安排保留。增加的冶炼占用从原制器安排中扣除，普通供养仍先占岗。手工/粮医分工不会凭签约突然获得冶炼能力。
- 冶炼仍实耗废料1、木0.5，产铁0.3/人/10秒；没有新炉、免维护车或人口奖励。
- 原有6+6名司机、双向1600载重、180秒单程、费用、共同运力竞争与地方预算全部沿用。
- 暂停撤回未到货批次；恢复须重新实际运到。湖滨改回其他工序会停止新补库，已出发批次按原价结清。旧约和已付账不重定价。

因而存在可解释的选择：本地修造更少依赖铁，但占更多工位；标准加工能节省工位、承担更大外供，却要支付产业分工、库存缓冲和跨城运输的成本。

## 3. 公共路线的独立验收

公共214沿其自己的世界底账继续，不能拿工业273的技术、库存或人口补给它。路线是：联合调度→矿岭普查与道路→木构第二车组→三城实付公用站→本城3200床安居→岗位接续/本地培训→共同预算与循环修造章程。

这条路线的本城出发仓是渠口，工业线是旧厂。审计须分清整座炉火城人口与实际出发片区的仓库、工位和住所。矿岭保有自身战前冶炼资产，参与贸易不等于本城自动获得采矿、电力科技。

公共路线允许先集中给本城建一处安居和接续工坊，三城共同承担站务、道路和有限生产职责。湖滨与矿岭不必重复建齐社区、劳务站与货场才算进入A3。

主动下调矿岭交通额度，观察冶炼检修与新订单停止，保留基本供养；恢复额度后检修、生产与贸易重新实付。此处测试的是撤回公共责任及供给恢复，不是人为制造无解饥荒。

## 4. 操作量、等待与界面

- 机构负责反复续办、补员与既定生产；玩家决定协约、生产取舍、额度和重大工程。统计提交决策、强制事件与导航/导出分开。
- 默认保持既有3类事务折叠、最多3项突出待办。没有新增主标签；供铁通过原章程中的文字链接进入原协约详情。
- “近600秒实耗/实到、库存、每批上限、往返时长”显示实际记录，避免将未来到货算成现货。零消耗可能是停产或库存够用，不代表0需求的预测。
- 章程说明直接显示规则返回的阻塞原因，避免只见灰色按钮却不知道工具必须先留给当地。
- 协约成本与新增生产责任分段阅读；工业补库选项只在相应章程阶段出现。公共早期不展示新选项。
- 实际生产历史折叠时不重复汇总整本账；暂停打开后立即展示完整累计，不能为性能删除历史。
- 刚竣工的公用站仍需下一轮实付续办，建设完成不等于当秒可以承担全部职责。真实试玩中的拒议、工具不足等待和恢复都保留。

现有计时：10秒一轮生产，60秒维护，600秒一模拟年；16×下600秒约37.5秒现实时间。贸易单程180秒约11.25秒，完整往返约22.5秒。正常供给缓冲能覆盖一趟以上，长时间等待应落在工程、培训、年度预算与事件，而不应迫使玩家每趟手点搬料。本轮保留时间规则，避免为了单条存档的测试方便偷偷缩短运输或快进历史。

## 5. 性能与守恒

原章程验证逐条生产记录反复扫描维护、授权和世界人口账。改为一次索引维护收据、顺序推进授权时点、顺序回放该人口账户的变动。仍检查同秒的经济/政策次序、每条实际投入、出料、人员上界与付款，不缓存可被旧状态污染的结果。

同一原生存档在同进程分别运行旧验证函数和新验证函数，报告中位耗时；不能把局部验证加速倍数当成整个游戏帧率提升。全量导入仍有地方负担、劳务、共同支出的长账回放成本，未来国家尺度需继续按真实剖析处理，不能先删账。

兼容边界：旧273及所有更早原件不改写；新协议值是显式选择标识。`cityGovernance schema1` 的原有配方、费用、维护语义没有改变。读取、折叠、供铁报告不改世界，人口总数只随出生死亡变化；城市合作、发现与换约不造人。

## 6. A3之后的固定边界

双路线与失误恢复通过后，按74的有限关口收口A3，不再因“再加一个城市设施”无限续轮。后续A4应首先解决当前城市群到地区尺度的接口：

1. 合作城市、管辖范围、居住地分别建账；当前合作成员不是已吞并国民，父地区与城市不得重复计数。
2. 共同事务支出额度不是现金，居民粮酬不是凭空货币。旧贸易/债务逻辑接入实际产业仓库及明确换算，不另造无来源财政。
3. 既有城市生产、资产、在途、住房与合同保留；宏观展示降低管理粒度，不能在升级时清空责任或发放人口/库存。
4. 用同一地点和线路事实制作简洁已知地区视图，处理百万→千万规模与政治整合的前置依赖，再复用现有国家功能。
5. A5三条完整先进社会、全球统一与首航、新玩家与跨平台验收仍是后续阶段。本轮没有实现它们，也不据测试数给出成品百分比。

最小下一段：两条A3路线都能进入一个实有人口、地方产业、公共负担明确的地区治理片段，并保留各自技术路径。不先回旧138档新增国家菜单。
