# 城市与区域整合实施规格

本稿保留实施前的设计记录。地区与首城模块现已实装；实际字段、成本、限制和规则测试以设计14、15为准，自然游玩进展以设计08为准。草案中的 `regions.city/migration` 等字段已拆到 `civilization.urban`，不能直接照旧数据示例继续接线。

本阶段把已运行的工业小镇接到第一座城市、河谷及两个新邻居。实施后应能回答三个实际问题：粮食和工业材料从哪里来，运输断了会怎样，居民为什么愿意留在同一共同体。地球统一仍按设计04至06推进，本阶段不以几个“占领”按钮代替后续国家与全球系统。

以下成本、阈值和时长是待实现的第一版配置，需以自然游玩调整。现有工业链与河谷存档是迁移起点，不重新开一套资源或人口模型。

## 1 当前基础与新增边界

当前已有本地人口名册、岗位、原料加工、电力流量、污染、领袖与制度四轴；河谷有独立12居民和独立食物/工具/药品库存，但仍通过固定产出和每60秒直接结算的特殊逻辑运行。下一阶段统一河谷与新节点的数据和运输，停止旧河谷特殊生产循环，避免两套代码同时产粮。

规模以设计04为准：正式小镇80至400人，城市400至3000人，城市群3000至20000人且至少三个城市节点。当前20人便触发的“河谷小镇”是已经运行的早期闭环称谓，木屋加长屋最大48床；不能把它当作正式城市规模的替代。旧档的 `village.town`、既有称谓与工业解锁全部保留，另记 `regions.chartered` 表示达到80人的正式镇制、`regions.city` 表示达到400人的城市条件，不回锁玩家已经获得的工业与制度。正式调整早期称谓须在完整实玩后单独处理。

当前机械阶段已经可以付费扩建第二座诊所和学堂，每座各2岗位，总上限分别为4。第二诊所成本木180、铁锭12、零件6、工具12；第二学堂木160、铁锭10、零件5、工具12，首座成本不变。自然实玩已出现36居民、2医护产药约0.315/10秒，而治疗要0.36/10秒，致使0.5药品的河谷出口长期凑不齐；扩建加岗才恢复贸易。这是下一阶段必须保留的供养约束，不能用免费提高产率掩盖。

首批内容仅三个邻居：

| 节点 | 起始情况 | 可以提供什么 | 真正缺少什么 | 首次联系 |
| --- | --- | --- | --- | --- |
| 河谷 | 现有12居民、已签的互助协定 | 农业余粮、种植经验 | 工具、药品、公共水务 | 沿用当前已发生的事件 |
| 铁轨镇 | 32居民、废弃货场、可修复机修棚 | 铁料回收、零件加工 | 食物、煤、维护工具 | 地理测绘后沿旧铁路线勘察 |
| 高地收容所 | 18居民、净水设施、旧教材；有人类和变异居民 | 医护与教育能力、山路信息 | 稳定粮食、燃料、通行权和政治承认 | 铁轨镇或河谷资料解锁山路 |

这些是本作新增地点，不标为原著已核实地点。首批节点的初始库存是剧情中原本存在的物资，创建时仅发放一次，不随读档或再次拜访刷新。

## 2 数据形状与模块职责

新增 `CivilRegions`，配置放入 `content/regions.js`，运行逻辑放入 `src/postwar/regions.js`。继续使用统一10秒经济结算和每秒世界计时；不另建独立setInterval。

```js
civilization.regions = {
  schema: 1,
  nextShipment: 1,
  nodes: {
    river: {
      discovered: true,
      control: 'independent',
      relation: 'trade',
      population: 12,
      cohorts: [],
      workers: {},
      buildings: {},
      stores: {},
      health: 80,
      trust: 50,
      unrest: 0,
      integration: 0,
      autonomy: 'local',
      rights: 'resident',
      promises: {},
      completedProjects: {},
      productionClock: 0,
      stableSeconds: 0
    }
  },
  routes: {},
  shipments: [],
  projects: [],
  expeditions: [],
  migration: { discovered: false, cohorts: [], reservations: [], nextParty: 1 },
  chartered: false,
  city: false,
  cityCluster: false
}
```

`control` 表示谁在实际控制；`relation` 表示已签的政治/贸易关系。两者独立。禁止一个布尔 `owned` 同时代表接触、占领、人口归属与政治整合。

本地继续使用 `State.game`、`State.stores` 与现有社会名册；通过 `getNode('home')` 的只读视图和明确支付/入库接口适配，不在切换地点时替换全局State。所有外部节点拥有自己的库存与供养，不把远方人口直接塞进本地岗位箭头。

首次接触前只保存地图发现信息。可参与经营的节点才初始化经济；独立贸易伙伴的固定生产可按已配置岗位结算，但未开放地方经营时玩家不能远程强行改岗。

已有基础、村镇、社会、工业结算只处理本地一次，`CivilRegions.settle(s)` 接在其后处理远方节点，不再次结算home。地区采用显式的节点经济视图，不能临时改全局State欺骗现有模块。每秒 `tick` 推进旅行/项目/整合，10秒 `settle` 处理经济；forecast在克隆上使用相同顺序。`init/validate/reset/refresh` 分别负责单次迁移、存档校验、重开引用和ADR原生界面。新版字段存在而损坏应拒绝导入，不当成缺省旧档重建。

## 3 现有河谷的单次迁移

先执行现有 `CivilVillage.init` 的 `schema:1` 援助补记，再迁移到regions，顺序不能反过来。

| 旧字段 | 新位置 |
| --- | --- |
| `riverKnown` | `nodes.river.discovered` |
| `riverAllied` | `nodes.river.relation = 'trade'`；控制仍为independent |
| `riverFood` | `nodes.river.stores.food` |
| `riverTools` | `nodes.river.stores.tools` |
| `riverMedicine` | `nodes.river.stores.medicine` |
| `convoys` | `routes.river.completedTrips` |
| `convoyClock` | 首次新运输的剩余发车时间，`max(0,60-convoyClock)` |
| `aidDelivered` | `nodes.river.completedProjects.initialAid` |
| `town`、`townStable`、本地健康 | 留在village，直到有明确后续迁移需要 |

旧版本没有在途货物，迁移不能凭空创建“已经出发”的货箱，也不能把历史运输次数再兑现一次。保留旧字段作为兼容记录可以，但 `regions.schema===1` 后禁止旧 `CivilVillage.settle` 再生产河谷粮食或运行旧convoy。

河谷初始12居民中配置4个农作岗位和既有1.76净食物/10秒的经济基线，保持旧档迁移前后的短期净收益接近。之后的设施、健康和政治政策再改变效率。未迁入的旧档默认创建名册时采用成年年龄组；不得一次迁移就凭空让一半居民退休。

迁移标记成功后再保存。损坏的新结构不应回退成“未迁移”并重复发物资，而应停止导入并给出明确错误。

## 4 科技与城市设施

先把现有知识与机械零件变成城市组织的实际投入。新增科技依赖如下：

| 科技 | 前置与发现 | 初稿成本/时间 | 作用 |
| --- | --- | --- | --- |
| survey 地理测绘 | records、handtools；已确认矿带且首次实际供电 | 知识40、工具10、零件4；240秒 | 旧铁路线和高地路线；只揭示有线索的地点 |
| standards 标准与计量 | school、mechanics | 知识60、铁锭20、零件8；300秒 | 城市住房、公共服务设施、统一货箱 |
| logistics 运输组织 | trails、preservation、records；至少一条已签贸易路线 | 知识50、工具12、零件8；300秒 | 真实在途货物、路线运力、运输岗位 |
| administration 公共行政 | records、standards；两个已接触居民节点 | 知识80、零件12；360秒 | 多地议约、行政档案馆、地方服务合同 |
| urbanworks 城镇工程 | standards、administration、power；本地≥80人且公共诊疗站和学舍已有实际岗位 | 知识100、铁锭40、零件16、工具20；420秒 | 街坊住宅和第二档工业容量；不要求先成为城市 |

不把更后面的化工、炼钢、车辆与铁路直接替换成以上几个节点；这些仍按完整科技树逐步加入。当前使用人力车与修复道路，不伪称已经修复货运铁路。

| 设施 | 条件 | 初稿成本 | 持续作用与限制 |
| --- | --- | --- | --- |
| 居住街区 | standards、电力已实际运行；至少一座已配员公共诊疗站与公共学舍 | 木400、铁锭40、零件10；最多8座 | 每座24床；与既有48床合计最高240，只扩容量，不赠送居民 |
| 街坊住宅 | urbanworks；医疗及口粮可覆盖下一批迁入 | 木650、铁锭70、零件20、工具20；最多4座 | 每座96床；两档住房全建后总容量624，为400人城市留出出生与迁入余量 |
| 公共诊疗站 | sanitation、standards、现有诊所；在扩住房前开放 | 木200、铁锭20、零件8；最多8座 | 每座增加4医护容量；连同2座诊所最多36医护，沿用每人0.2粮+0.1废料→0.15药品的实际配方及效率修正 |
| 公共学舍 | school、standards；在扩住房前开放 | 木180、铁锭12、零件6；最多4座 | 每座增加4教师容量，连同2座学堂最多20教师；原有木料→知识配方不变；每位实际在岗教师可服务20名未成年居民 |
| 灌溉田片 | irrigation、standards、已维护的泵站；不要求城市 | 木160、铁锭6、工具18；最多6座 | 每座增加8农夫容量，连同4块试验田最多64农夫；沿用每农夫正常灌溉2粮/10秒，断供降为1.4的规则，不凭建筑自动产粮 |
| 制器间 | standards、现有工具台 | 木160、铁锭20、零件6；最多2座 | 每座增加4制器工容量，连同原工具台最多12；仍实际消耗木料与废料，不生成免费工具 |
| 行政档案馆 | administration | 木180、铁锭20、零件10、知识40 | 协调容量增加2；每10秒消耗知识0.04，缺料时容量加成停用，但不立刻吞掉地方 |
| 车队场 | logistics | 木180、铁锭20、零件8、工具10 | 开放运输工；每2人支持一条常规往返，不可同时在其他行业生产 |

公共设施先可建可配员，住房才出现；不要把服务扩容锁在“先达到80/400人口”后。400居民的基础治疗是4药品/10秒，现有4医护只有0.6基础产量，远不够用。医疗负载应显示实际药品净流量和贸易/迁入承诺，不能仅凭有诊所就显示“服务充分”。教育覆盖按真实儿童和在岗教师计算，知识库存本身不能替代教学岗位。

`urbanworks` 将矿井、煤井、冶炼炉、机械工坊、发电机房的可建上限从2逐步开放到4，第三/第四座仍按付费建造和岗位投入生效；不在研究完成时直接增设施或工人。用同一个 `CivilCatalog.buildingLimit(s,id)` 供建造按钮、保存校验和岗位置顶规则使用，避免UI可建但导入拒绝，或读档绕过科技。农夫、医护、教师、制器工沿用同一份岗位人数，容量由旧新设施相加；`CivilRules.rates` 中目前写死的 `farm*4` 要改用统一容量，不能在新模块再产一次粮。旧设施计数和已保存岗位不丢失。

容量校核采用保守的效率1、均分口粮和已修蓄水池，不依赖帝国或中央统筹才能维持城市：400人最多消耗43.2粮/10秒，32医护另耗6.4粮、3.2废料并产4.8药；32农夫正常产64粮，泵站失养时只有44.8，必须体现断供风险。32农夫+32医护+6教师+8制器工+14回收工+6运输工约98名成年劳动者，仍留有工业、木材和其他岗位空间；14回收工的11.2废料扣去医护3.2与制器4.8后，尚有3.2供机械等用途。仅列岗位容量不算验收；实际要把工业用工具、车队旅粮、地区承诺和迁入开支也放入同一净流量预览。400人城可由本地农业基本供养，贸易提供余量和发展资源，不能因唯一邻居停运永久卡死主线。

### 4.1 有来源、有成本的批次迁入

48→80→400的人口由持续迁入与既有出生累积，不作为阶段奖励发放。初期每60秒单人到访可继续；一旦启用地区接纳计划，该目的地旧到访入口转由同一迁徙队列管理，避免原到访与新计划同时生人。暂停计划只暂停付费批次，不删除名册或既有居民；零资源时仍可从名册接纳低速单人到访，但要有床、6粮储备且无饥饿。

第二个邻居被发现后，通过一次事件获知地区散居者的登记名册。首版配置480人，只初始化一次，按儿童、成年人和老年人分年龄组保存，含人类和变异居民。它代表尚未纳入玩家经济的独立散居人口，不是第四座可经营城镇：不产玩家资源，不领本地口粮，不供玩家任意征税或调岗。源名册、接纳途中和目的地三处人口守恒；此池用于保证首城迁入路径，耗尽后不能靠读档补满，后续更大人口池须由新的地区内容提供。

接纳计划须有车队场、公共服务岗位和已登记条款。每批最多8人；发车时按实际人数支付每人6粮、0.2药品、0.2工具，另占2运输工的往返运力，单程120模拟秒、空车返回120秒。可用两组车队错峰发车，但每组都占真实岗位。费用用于途中的供养、基础治疗与安置器具，不能在到达时返成资源奖励。源名册中的实际年龄组被移入在途记录，到达才加入本地；例如一批可以是5成年人、2儿童、1老人，而不是8个即刻上岗的无龄劳工。迁入后继续用现有每600模拟秒一历史年的规则成长、退休和死亡。

发车要同时检查并预留住房、旅途物资、到达后至少120秒的口粮，以及新增人口后的医疗净流量和儿童教学容量。预留床位同时约束旧单人到访和出生容量，不能由两个循环各占一遍。住房临时损失则旅队停留在有补给的接纳点等待安置或带人返回，不删人；人员在途时仍有年龄与口粮记录，已消耗旅费不退款。到达失败不得在源与目的地同时保留同一组居民。

480人源名册加既有本地人口足以覆盖首城400人的正常路径，按8人一批、两组错峰且无停运，新增352人需约5280模拟秒（4倍速约22分钟），实际还要建设和储备时间。这是理想连续发车估算，不是承诺实玩时长；自然实玩应记录死亡、儿童比例、服务扩建与财政停顿后是否仍能到达400。只改变批量和成本不能跳过人数、年龄和资源检查。

## 5 运输是实际在途物资

一条路线只开放已知目的地。线路记录 `source、target、travelSeconds、capacity、assignedWorkers、condition、enabled、nextDispatch`。首条河谷路单程60秒，铁轨镇90秒，高地120秒；按统一倍率推进。

出发必须同时满足：道路可通、运输岗位足够、出发仓有全部货物和旅粮、目的地存在。成功出发时从源仓一次性扣除货物，创建带唯一ID的shipment；到达时仅向目标仓入库一次。资源守恒核对必须把在途货物算进总账。

初版不做无限自由商单列表：每个节点先有一份明确互惠合同，例如本地送工具/药品，河谷回运粮食。发送去程物资后，对方收到并满足本地口粮储备，才扣本地仓并创建返程货物。源仓、在途与目的仓三者不能同时计算同一批粮食。

运输工是真实劳动力。原生岗位列表分配运输工后，再在路线中分配其服务能力；路线总分配不得超过运输岗位人数。首版将运输劳动抽象为整个路线班组，不模拟每位司机的具体位置，但必须吃口粮、占岗位。运输工退休/短缺时，已付费发出的货物按原计划抵达，下一趟停止；不得通过反复改岗复制船车或抹掉在途货物。

道路受损或外交中断时，未出发订单不扣款。在途遇阻进入 `held`，货物仍留在shipment账上；有“修路续行”和“带货返回”两种恢复途径。没有无上限倒扣库存，没有静默删货。首批不设置随机永久丢失关键科技物品。

每个节点先保证自己的口粮底线。河谷低于两轮居民消耗不得输出粮食；工具和药品合同可暂停。对方没有粮时，不能仅凭玩家交了一件工具就无中生有地兑现12粮。

## 6 行政容量与制度实际生效

容量使用现有 `CivilSociety.capacity`，叠加实际正常运行的档案馆。解释统一为正在协调的公共治理责任：

- 本地城市占1。
- 仅有通行/贸易的独立节点占0，不收税、不征兵，也不能改其岗位。
- 加盟或正式整合的节点占1，承担相应服务与共同规则。
- 军事占领且尚未恢复地方治理的节点占2，管理压力更大。

超容量不阻止正常到货，也不自动把已加入地区变成敌人；停止新的整合增长，并增加行政知识消耗与当地不满。玩家可扩建档案馆、增加教育、重议地方权力或把某节点退回贸易伙伴关系。必须保留恢复路线。

政治四轴在多节点中对应不同规则：

| 维度 | 本阶段的实际作用 |
| --- | --- |
| 结构 | 沿用现有协调上限；联盟/联邦更容易获得自愿加盟，但共同公共项目需要地方同意 |
| 领导产生 | 保留现有继承；任期变化不清除条约，继任者也不能免费取消已兑现的承诺 |
| 宪制 | 成文宪章明确承诺和公民资格；违约有可追溯合法性损失，不能靠切政策清除历史 |
| 地方权力 | 自治节点可保留地方岗位优先级，中央取得的定额物资较低；统筹节点可调整公共产业，但占领期或未经同意的干预增加不满 |

“中央统筹”不等于可以直接改独立贸易伙伴的岗位。先建立合法的治理关系，再讨论权限。既有帝国/中央增产修正不再额外乘一遍区域修正，避免同一政治效果重复计算。

## 7 和平加盟与整合

和平路线按 `unknown → contacted → passage/trade → associated → integrated` 推进。各状态都有真实用途，不要求玩家重复点同一按钮刷进度。

1. 接触：勘察花费口粮、工具和时间，得到节点现状与需求。没有首次相遇就把全地球势力摆出来。
2. 通行/贸易：双方承认路线和明确货物合同，开始实际交付；拒绝当前条款可以以后重谈。
3. 加盟议约：至少3次成功双向交付、关系≥60、行政容量足够，提出公共责任。地方代表要求住房/水务/公民资格之一，形成可完成的项目，不只是关系+10。
4. 共同服务：物资实际运到并由当地建设项目消耗，项目持续180至300秒；不再从本地远程扣款就瞬间修好地方诊所。
5. 整合：代表接受条款后，至少持续600秒满足口粮、健康≥60、道路通行、行政服务、既定公民资格和承诺。进度达到100才形成正式共同治理。断供先暂停，长期失约才缓慢倒退；恢复后接着推进。

河谷既有援助与贸易次数应计入已经履行的证据，但不能直接跳到integrated。首批12工具/40粮援助已用于早期关系，不能再当成新诊疗站的建设成本使用两遍。

“暂缓加盟”保留贸易，不清空关系。不同政体均有可行和平路径，只是成本和条款不同；不得把特定政体设为唯一能继续主线的答案。

## 8 公民权与变异居民

高地收容所通过具体代表提出政治资格问题，河谷代表也参与。人口类别记录为居民的身份与需求，变异身份不改变基本劳动价值，不自动增加犯罪或不满。

先开放三种有实际后果的制度：

| 公民资格 | 权利与负担 | 整合影响 |
| --- | --- | --- |
| 平等公民 | 长住居民具有同等公共服务和代表资格，包含变异居民 | 服务成本按实际人数支付；和平整合较稳，既有排他派系可通过事件表达反对 |
| 居住资格 | 初到者登记，连续履行共同体义务后取得资格；适用相同条件 | 资格有明确倒计时与可达条件，等待期间仍有基本食物和医疗；整合较慢 |
| 分层资格 | 统治地与附属地权限不同 | 可维持贸易/附属关系，自治诉求更强；不得把未平等承认的地区计入“共同法完全统一” |

资格不能按外形随机判定。若玩家使用分层资格，后续仍可改革和赔补承诺，不封死地球主线。地方人口的税/兵贡献、公共支出与政治参与从权利规则推导，不只给一颗“道德分”。

## 9 冲突占领与和平整合分开

首批铁轨镇设一个可谈判的守备集团，提供运输争端和道路安全问题。军事路线待民兵轮值与守备器材落地后才开放；在只有工具的版本，不先显示“进攻”。

军事力量必须来自成年人口的实际守备岗位和已制造器材。出发或警戒期间不能继续当农夫。补给扣口粮、工具维护和药品，伤亡从参与人员中扣除，不能凭战争按钮生成部队。

战斗先采用有上限的阶段事件：警告/谈判 → 部署 → 补给检查 → 交战或撤回 → 停战条件。事前显示双方可见力量、路程和物资需求，不声称精确预测胜率。短缺可暂停或撤回，不一秒钟自动团灭。

胜利只产生 `control:'occupied'`，`relation:'ceasefire'`。当地人口、库存和工厂仍在原节点；缴获必须单独记账，不能让所有本地资源同时归两方。占领初期增加守备和行政成本，地方产业因安全与参与不足降低效率。

从占领走向共同治理需要恢复口粮/医疗、处理赔补或自治承诺、开放公民资格，再开始整合计时。反抗过高先引出罢工、停运和议约事件；真正失去控制必须有预警与可恢复状态。不能将“打赢一次”直接当成永久收复完成。

## 10 城市与城市群的判定

正式镇制先要求本地≥80居民、住房足够、公共诊疗与教学岗位运行、健康≥60、无饥饿、至少一条往返贸易正常，连续维持180秒。确认镇制只登记 `chartered` 和开启下一步工程研究，不赠送人口或库存。

第一座城市使用设计04的400人量级及明确的公共系统条件。首版条件为：

- 本地至少400居民，不包含地区散居名册、在途迁徙者或邻居人口；住房未超额，成年劳动力覆盖必要岗位。
- 现有矿业、冶炼、机械与供电链正在运行；至少4电力实际被生产设施使用。
- 诊疗站与公共学舍有实际人手，实际产药扣除治疗及合同后不为负，所有本地儿童有教学容量；健康≥70、无饥饿、污染<40。
- 公共行政正常，已履行至少一个邻居共同服务项目。
- 食物储备覆盖至少120模拟秒的居民消费，工具≥40、铁锭≥40、机械零件≥20。
- 全部条件连续维持300模拟秒，再通过议事事件登记城市名称与公共职责。

每次实际10秒结算记录健康供给证据，不能仅由按钮点击瞬间的满仓通过。检查教学、药品与资源时共用实际规则/forecast，避免另写一套乐观比例。历史上获得的镇制和城市称谓保留；人口回落、缺药或停电使当前发展稳定度下降、后续解锁暂停，不拆掉已建房屋，也不让读档反复领取建城事件。

城市群仍是下一阶段：至少三个真正城市节点、全地区≥3000居民、共同治理、连续双向运输和行政容量覆盖，稳定600秒。外部节点也需要运到的建设材料、真实扩容人口、当地供养和公共岗位，不能把12人的河谷改成城市布尔值。本轮最多做到首城400人与两至三个邻居的加盟/整合；624床的首城和两个同级住房容量即便全住满也不足3000，因此不实现城市群成立按钮，不将三地加盟标成城市群完成。下一轮再引入更高密度城区、铁路和地区服务扩容，消除3000人门槛前的实际容量缺口。

## 11 渐进 UI

继续用ADR顶栏地点、原生按钮、岗位箭头、库存悬停和事件窗口。

- 矿带和供电前仍只有现有地点。
- 地理测绘后增加一个“地区”地点，只显示已发现的节点名称与路线。未发现地点不显示锁图标列表。
- 点节点名称打开该节点的原生事件窗口，先显示居民与当下需求，再显示当前真正可执行的贸易/公共项目/议约选择。
- 加盟前仅看见合同与交付；取得地方经营权后才展示地方岗位优先级。优先用“粮食/修复/公共服务”三类工作计划，按真实成年劳动者分配，避免一开始重复十二行全套岗位界面。
- 第二次居民接触后才出现接纳计划；有公共服务岗位后才出现居住街区，80人镇制与城镇工程后才出现街坊住宅。库存悬停显示下一批新增口粮与药品负担，名册保留儿童/成人/老人，不额外铺一页人口图表。
- 运输状态以“已发出、在途、抵达、待补给”短句显示，库存悬停按节点给流量；不能把在途货物当可建造库存。
- 军事入口在部队、器材、冲突三项都出现后开放。
- 议事屋只新增已经触发的公民资格和地方议约，不把尚不存在的税制、银行或太空法做空壳按钮。

## 12 实施顺序与验收

### A 河谷迁移和运输

先完成regions单次迁移、源仓/货仓/目标仓守恒、运输岗位、在途存档。以现有自然小镇档迁入，检查所有河谷库存与已完成次数不变，第一趟新运输只在到达后入库。

### B 两个邻居与行政

实现survey、logistics、standards、administration，先公共诊疗站、公共学舍、灌溉田片和制器间，再居住街区与付费接纳。发现铁轨镇、高地收容所，各有不同供需。至少两条运输同时运行，不能共享同一份运输岗位或货物。旧档第二诊所/学堂和4人容量应直接接续，不重买既有建筑。

### C 公民资格和和平加盟

一次自然游玩走通河谷共同项目与加盟，另一路完成高地收容所的资格议约。制度四轴必须实际影响容量、开支或当地权限；读档不能丢失地方承诺。

### D 冲突与恢复

有民兵和器材后再验收铁轨镇争端的谈判与占领分支。占领状态不能满足和平整合或城市群条件；战后重建可恢复，战败不删除其他独立节点的进度。

### E 第一座城市

从自然小镇档继续经营，经80人镇制与urbanworks达到400人第一座城市，覆盖两档住房、医疗与农业能力、付费迁入、稳定供电、跨地物资和至少一次领袖交接。分别记录48、80、约200、400人口的真实岗位/净流量/库存和存档，验证每一步都有可支付的下一项扩容。记录真实时间，不在浏览器注入人口/库存验证城市成立。既有出生与迁入都必须按实际年龄入册，不能用整批全成年人口掩盖劳动力不足。

### 必须通过的规则检查

1. 同一shipment重复到达不重复加库存；读档重放与暂停恢复均守恒。
2. 断路在途货物仍在账上，返航只能返还未消耗的货物，旅粮不能无限退款。
3. 河谷旧逻辑与regions新逻辑不会双重产粮，旧援助不会再次发放。
4. 任何节点不输出超过库存的物资，节点口粮与承诺项目的优先顺序明确。
5. 路线分配、守备分配与生产岗位总人数不超过成年劳动力；退休或伤亡后先收缩计划，不能出现负采木工。
6. 行政超容量导致可恢复的成本与不满，不让已到货物消失或自动宣布战争。
7. 加盟、占领、整合、城市、城市群五种状态分别验证，不能互相代替。
8. 变异居民适用所选公民权规则；平等资格不暗中降低其产出，居住资格有实际可达的转正条件。
9. 继任、改革和读档保留节点库存、条约、承诺、项目与在途货物。
10. 真实自然路径和规则桩测试分开记录；三地城市化没有实跑完成前，不称城市群已经验收。
11. 新旧住房上限、岗位容量和建造科技共用规则；不产生“按钮允许、存档拒绝”或写死旧16农夫导致新田片无效的分歧。旧4医护档可持续扩至400人所需医疗产量，所有药品仍支付食物与废料。
12. 源迁徙名册、在途人员与目的地人口之和守恒；中途存读档/返回/出生/退休不复制人员，住房预留不被另一入口重复占用。未成年不提供成人岗位。
13. 迁入前可先扩建医疗、教育、粮食与住房，所有设施均不以未达成的400人城市为前置；药品不足会停迁入/贸易，追加付费设施和实际岗位能恢复，不能仅靠研究一次恢复免费净产量。
14. 第一城的400人不统计独立邻居或在途人口；三节点人口不足3000或未完成城市化时，城市群始终未达成。

## 13 当前代码审计结论

本轮只读审查未发现矿业到发电链存在必然卡死或免费工业产出的具体错误。实际与forecast均按基础经济、诊疗/河谷、公共行政、工业顺序结算；旧ADR独立收入循环已经禁用。10,000组确定性稀缺资源探针中，工业返回flow与真实库存增减一致，没有负库存或超额用电。该检查不代替浏览器实玩，也不证明未来区域系统已经实现。

仍需后续完善的抽象包括：工匠固定木料收入尚未纳入代际名册、现有商业/公共仓尚无货币与税制、河谷人口尚未按完整年龄与岗位运行。前两项不能靠区域改名宣称完成；河谷人口将在本阶段迁移中接入统一规则。
