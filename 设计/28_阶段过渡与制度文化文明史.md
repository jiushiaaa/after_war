## 1 退役的是重复操作，不是资源与责任

| 阶段 | 主操作 | 旧内容怎样留下 |
| --- | --- | --- |
| 维修间／收容所 | 添火、采木、找食物、少数建设与首次配给 | 必要按钮直接可见，玩家能理解火、温度和物资来源 |
| 村镇 | 岗位、粮药、教师、道路、定期维护 | 一次性基础设施进入“已建设施”；普通维修由实际在岗人员实付处理，缺人缺料仍显示原因 |
| 城市 | 公用服务覆盖、住房、产业投入、运输、制度与地方职责 | 炉火成为维修间设施／应急入口；日常供暖由已建服务负责，研究从零散按钮整理为科技入口；小型采集收在应急行动里 |
| 城市群／国家 | 地方服务标准、预算、交通、重大工程、社会契约与对外关系 | 正常节点按摘要与地方计划管理，异常可下钻；本地岗位／仓库仍真实结算，不把自动化变成全网免费生产 |

阶段提升不是删除低级能力。灾后仍能手工采木、找食物、点应急炉、恢复一个实际成年人；只是平时不再要求千人城市每分钟点同一根木柴。暂停自动计划停止**新的**支出与任务，既有旅队、在途货物、工程材料和已到期责任继续按原契约处理。

自动化只能执行已授权动作：给定资源上限、最低储备、实际岗位与当前资格，检查后支付一次，失败等待恢复。它不能免费调出工人、绕过施工、反复买到同一件装备、替玩家同意改制或对外战争。规模越大，玩家决定的是预算与优先级；物资仍由具体地点生产和运送。

## 2 一次性建筑收纳与明确科技树入口

**先做纯显示改动，不改变经济。** 建筑按钮按当前真实规则分为“可建／可扩”“正在施工”“已建与维护”三处。当前上限为1且已完成的工坊、道路、粮棚等移入折叠“已建设施”，保留数量、作用、维护和相关入口；隐藏按钮不删除building、seen、工程／付款记录。

可重复建筑只在达到当前容量上限时退出主建设列。未来科技提高buildingLimit后，应自动回到“可扩”，不能因为曾经收纳就永远找不到第三座工厂。未完工程始终保留在任务摘要，不能先按计划数算床位或供电。公共服务、Services工程与地方Municipal各读取自己的真实完成记录，不用DOM里有没有按钮推断完工。

工坊出现后提供固定、命名清楚的**“科技”入口**，不把已掌握数量的悬停文字当唯一入口。默认显示当前研究、现在能研究的技术和直接下一层；可切换“科技树／已掌握”。树按生存与卫生、工业与能源、公共组织、交通等实际已接入分支整理；前置连线来自同一requires数据，成本、发现条件和运行限制读取原规则。

已掌握技术可查看作用和相关设施；未满足前置显示缺哪一项；未知遗迹线索只显示尚待调查，不开局泄露机器人、聚变和首航全部细节。文档中的未来科技没有对应规则就不伪装成可研究节点。研究仍实付材料、占唯一研究任务与时间；打开科技树不自动研究、不退款、不补进度。

经济制度、文化和宗教不塞进科技树作为加成技能。公共记录、会计、通信、教育可以提供执行能力；采用某种所有制、分配规则或信仰政策则经真实社会事件和制度程序决定。

## 3 从添火交接到供暖／能源

集中供暖首片现已实现，确定规则见设计31。旧档与未交接城市继续原炉火，工匠每300模拟秒有余火时实付1木守火；旧火熄灭仍要5木重燃。电站存在本身不代表热网已经建成。

历史首城之后研究“集中供暖”（公用工程＋动力前置；钢12、零件8、知识80，300秒），再通过实际材料与两名成年人300工秒建设供热站。每站电动2工、煤0.8、零件0.02、同池电1供600人；手动4工、煤1.2、零件0.02供300人。每地独立结算，水务和药剂已经使用的电不能再用一次。

交接须玩家点击明确入口，近期试运行覆盖现居民及真实在途家庭、下一轮完整生产预测仍够，并留下三轮锅炉煤件；home另须至少2名实际采木工。交接后旧火／温度计时停止，工匠固定2木／10秒退出，旧火温历史值不再授权建设或接纳。原生维修间转为公共维修间，5木可付费开启120秒、20人份应急工作间，不能供养千人城或放行迁居批次。

断供先呈现缺口，阻止新增接纳和持续城市资格；保留住房、资源生产、供热工程和修复路径，不新增瞬间冻死规则。家庭预测按实际儿童、成人、老人计算，不能把在途孩子重造为未来工人。home零人恢复只允许既有来源逐人、原6粮费用与住房同时满足，合计含预留最多20人；地方没有借用home应急的特例。

自然游玩已研究并建成两站、安排4名供热工，实付煤1.6／零件0.04／电2后提供1200人份，覆盖1164居民；130907秒实际交接。手动降容、真实撤岗断供、5木应急及原样读档、恢复4工电动均已观察。其他缺煤、缺件、电力竞争、地方运材交接与零人口恢复由规则测试验证，不冒充所有情形均已自然发生。风力首片现按设计37实装并自然验收；水力、核能、储能与区域电网仍待后续实现。

## 4 经济路线是可组合制度，不是二选一口号

现有四轴分别是共同体结构、领导产生、权力约束、中央地方责任。资本主义／社会主义不能代替这四轴，也不能决定是否有选举、是否是联邦或必须采用哪种文化。新增经济维度逐个在真实问题出现时开放：

| 经济维度 | 可组合方向 | 要落实的账与代价 |
| --- | --- | --- |
| 生产资料所有权 | 公共、劳动者合作、私人、混合 | 明确谁拥有哪一处设施／原料，谁承担维护，产出进入谁的仓；转让需实付对价、补偿或明确争议账 |
| 资源配置 | 公共计划、合同配额、受监管市场、混合 | 计划要实际信息与协调能力；市场要真实库存、买方余额、价格和合同。两者都不能解决不存在的产能 |
| 劳动与经营权 | 公共任命管理、职工参与、合作社表决、合同雇佣 | 决策／协商占用工时和行政资源，劳动报酬真实支付；不能同一工人在公共和私人生产里计两遍 |
| 分配与保障 | 基础公共配给、工资／劳动份额、公共分红、社会保障 | 每项支出来自对应公共或经营账户，老人和伤病人口继续吃饭；保障扩大需要持续财政，不是固定“幸福＋10” |
| 投资与融资 | 公共预算、社员积累、私人投入、借贷 | 新资本必须来自既有资产或显式一次发行；债务记录买家、期限与偿付，不用融资按钮生成钢材 |
| 公共规则 | 税基、竞争／劳动保护、公益服务、地方财政权限 | 只对实际税基征收；限制和保障改变成本与供给，执行需要记录／争议处理；私人或合作财产不随换领袖清零 |

“资本主义路线”可以作为私人／混合所有、合同雇佣、市场投资占主要地位的**政策组合名称**，而不是天然增产或天然邪恶。经营利润必须是实际收入减原料、工资、维护与税款；私人投资并非免费公库收入，公共服务需采购／税收／公共部门承担。监管与保障可以改善参与和风险分担，也会占用真实资源和协调能力。

“社会主义路线”可以体现公共／合作所有、社会化投资和保障，可搭配计划配置，也可保留市场或合同配置；政治四轴仍另选。公共投入能统一承担长期服务，但项目判断、信息、劳动与维护都要有人负责；合作经营可以分担组织权，也有协商和资本积累成本。不能把“公有＝无限资源”或“计划＝必然失败”写成规则。

玩家可长期混合：水务公共经营、工坊合作经营、非基本消费品合同交易；也可改革。展示具体设施所有者、预算与权利，不必强制给每套组合贴现实政党名称。没有实际私人／合作账户以前，当前公共仓继续如实称公共仓，不提供只有名字和倍率的所有制切换。

最小落地仍按设计16／27：只试一处作坊，明确转移一批原料和实际岗位；公共原配方停止向原仓重复产出；完成一次生产、报酬、采购、缺料与恢复。之后才开放凭证、税和融资。改制有动议、公开条款、过渡时间及旧合同处理，不能换一个图标就免费没收／复制全城资产。

## 5 文化与宗教是社会生活，不能当万能增益

首轮从已存在居民与历史生成一个具体社群，不新增“信徒人口奖励”。文化背景、信仰、职业、human／mutant身份彼此独立；一个地方可有不同信仰，无信仰居民也有文化。信仰不决定善恶、智力、技术适应或政治忠诚，不把某一种信仰写成天然敌方。

文化先做地方教材／档案交流，沿用设计27的真实教师、木料、知识和服务覆盖。宗教最小案例可以是具有具体葬祭／互助需求的居民团体：提出公共空间安排→选择共享会堂、社群自筹或公共补助→有真实材料与组织人员→持续执行开放／使用条款→形成地方关系和履约结果。场所可以兼容世俗纪念活动，不因名称变成免费医药或科研产地。

政治选择分开处理：信仰自由与基本公民资格、公共机构是否中立、某机构是否得到公共支持、宗教组织是否参与特定公共服务。公共支持有预算与同等使用规则；社群自筹必须从其真实可支配资产转入，不能把屏幕外捐献当无限物资。组织参与医护或赈济时仍需合格岗位、药品和口粮，不能把同一服务在诊所与教团重复计数。

统一教材／公共纪念可以降低某些协调成本，但会引发具有具体利益和历史的地方协商；保留地方语言／仪式需更多教材、工时和行政支出，可能改善该地参与。限制、强制或排斥应带来真实权利争议、地方关系与人才选择后果，不能用“控制＋20”抹掉矛盾。影响有对象、上限和时限，不能无限办仪式叠全网产出。

这些内容通过已有学校、地方代表、死亡纪念或条约事件渐进出现；开局不摆宗教百科、文化胜利树或独立“信仰货币”。国家阶段再扩公共教育、学术自由、媒体与多社群代表制度，仍以真实支出与权利承担后果。

## 6 右下角“文明史”：重大事实，不是刷屏日志

右下角新增稳定的**“文明史”入口**，与存档、速度并列；点击打开原生可筛选／分页记录。左侧即时消息继续负责短期提醒。文明史默认每页20—50条，按年代、地方、制度／人物／科技／建设筛选，未解锁类别不提前占位。

应记录：首次稳定聚落／城镇／城市／城市群；重要科技首次完成；主要工程首次投入服务；领袖死亡、退休与实际交接；初次配给、四轴确立、改革与取消／退款；来源／地方条约、资格选择、共同职责；重要遗物取舍、战争／停战及重大文化决定。日常产出、每次添柴、每位迁入、普通维修不逐条写重大史；可在年度摘要聚合，不掩盖真实人口／财务账。

记录“发生了什么、谁作了什么选择、实际成本／即时结果、涉及哪里、随后怎样兑现”，不写模型猜测的动机或尚未发生的好结果。一次选择与后续履约／失败可通过parentKey关联，不能事后改写当时的选择。开放事件但未提交不算采纳；失败按钮不写成功历史。记史失败不得反过来执行第二次交易。

建议最小结构如下，具体接口由本轮实现统一：

```js
c.history = {
  schema: 1, introducedAt, nextId: 1,
  entries: [{id, key, kind, at, year, generation, nodeId,
    summary, choice, effects, sourceRef, parentKey, origin}]
};
// origin: live / legacy_snapshot / legacy_record；未知精确时间用null。
```

稳定事实键用业务身份去重，例如 `research_<id>`、`city_<node>`、`leader_death_<generation>`、`succession_<generation>`；可重复改革需自己的唯一事务序号。**死亡和交接必须分键**：当前Society.history的to是实际交接年，不能推断成领袖死亡年，尤其玩家可能多年后才确认继任。

只有业务所有者成功提交后才能append，不能挂在notify、渲染、悬停或通用done的字符串上；当前通用done会清某些失败事件，不能据此判定成功。史录是只读审计投影，不是科技、建筑、人口或财产的权威来源；修改史录、打开历史、选择分类均不解锁任何能力，也不能用历史条目代替Services／Origins／Finance原凭据。

旧合法档缺history时：先完成Society等旧字段正规迁移，再登记一次接入基线；已有任期记录可保留其可靠的from／to与reason，但精确秒数未知留null。过去已掌握的技术与城市只写“接入时已有”，不编造何年研究、花了多少或玩家选过什么。现任已经死亡但旧档没有死亡时刻，只能记录接入时状态。显式坏history不静默清空重建；重新加载不再补一份基线。

校验类型、唯一键／ID、合法kind、字符串与载荷大小、非负年份、at不晚于elapsed、live的year与at对应、来源标记及可靠的业务引用。只接受可序列化字段，显示使用文本而非HTML。运行时追加稳定排序；未知旧时间单独标注，不能为排序伪造事件时刻。重大历史不能因UI只显示最近五条就被静默丢弃，历史归档与存档大小上限须明确处理。

## 7 顺序与必须验证的边界

“已建设施收纳＋明确科技入口＋发展史”与真实供暖交接已分别完成自然验收。下一步做一个文化／宗教空间协议和一处合作作坊，不同时开放所有主义、税率和宗教目录。设计26共同预算继续与地方扩城推进，不能因新增主题把已授权主线丢掉。

验收重点：收纳后成本、冷却、工程及状态不变；提高建筑上限后可扩按钮重现；科技树与真实前置一致；单击／双击／旧弹窗只记录一次成功；取消改革的退款有独立事实；死亡年和交接年不混淆；旧档迁移不虚构史；删除history后其余游戏状态与记史前一致；伪造史录不给资源或科技。供暖必须测旧新燃料不双扣、无人／缺煤／断电停供、手动恢复、跨倍率／读档不重复计时，以及地方不能借home温度直接通过检查。

资本主义／社会主义组合的验收是实际资产、劳动、工资／份额、税基与服务责任守恒；文化宗教的验收是实际参与者、场所、费用和权利后果。不能用一个路线名称、一次加成或一段史书文字代替完整规则。
