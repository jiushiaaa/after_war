# 地方危机救济与生产恢复

2026年11月1日。**本轮已实现救济首片及第5节农工修正，规则完整恢复通过；自然浏览器尚未加载和验收。下文为原方案，实际差异与证据见文末及专门验收。** 现有Finance返赠、普通贸易返程两项锁车修复已进入本地提交 `457705f`，全套474/474通过；这只证明货运恢复规则，不代表铁轨危机已解决。下一片继续当前真实存档，不回到健康尚好时，不补资源、健康、人口或工时，不发布。

## 1 真实起点与需要解决的闭环

原始69号档已从正常UI原样恢复，固定证据为 `验证/存档/自然游玩_集中供暖交接与铁轨恢复运输.json`，134707模拟秒、1×。铁轨仍有113位居民、75名18至64岁实际劳动力、14名儿童；健康0、粮0，工具和煤仅余浮点尾数。地方有木约3493、废料约24777、药品约2757，原仓库和人口账均保留。

铁轨已建3座田片、4座诊疗站、1座学舍和3个居住街区。当前14农工、9医护、4回收工、1采木工、1教师及2冶炼、2机械岗位；没有制器间。农工真实上限为原6岗位加3×8新岗位，共30。12号街坊尚在供料，缓冲木500、铁12，仍缺铁48、零件20、工具20。1875号普通贸易车正去往铁轨，剩36秒，携粮12、煤2、工具1；不得把它改成救济车或替换货物。

原67完整规则回归已经揭示两层问题：

1. 返程锁车已修：只出口铁与零件时不再要求无关口粮，实际货物仍须实付。贸易与市政运材继续，135313秒补齐原12号工程材料。
2. 健康与生产仍无法自行恢复：原67无补数续跑3600秒至137675，健康仍0，原工程360秒施工一秒未动，不能再开制器间或回收场。人口114→108是原名册正常年更；不能将这一损失抹去。

原69当前每10秒口粮需求为13。健康低于30且结算开始时缺粮，实际产率乘 `0.75×0.65=0.4875`。6名旧农工无工具产粮2.34；即使当前14农工都付足工具，总产粮也只有 `(6×0.8+8×1.4)×0.4875=7.8`，还未支付医护等岗位粮耗。普通贸易的粮12不能承担整个地方的持续缺口。现配工按正常产率计算，不能把其名义产能当作病弱饥饿时的实际产出。

本片终点建议定为：**原69收到实付救济，恢复实际进食和治疗；健康真实回到施工允许值；12号街坊正常完工；随后付费建成地方制器间、回收场，在停止新救济后验证粮与工具能够持续生产。** 不在此片扩张人口、放宽城市群门槛，或宣称全工业链自给。

## 2 最小救济运单

增加一次性的“送一车救济物资”，沿已发现、已同意共同治理的地方路线发往其原仓库。不新增研究、救济设施、第二仓库或车辆。只要求节点和路线合法、共同治理关系允许接收；派车时检查实际道路、原2名运输工、原货车空闲及home支付能力。

**健康≥30、当地有粮／工具、有正净产出、12号住房完成、城市资格、供热交接或共同预算按期履约，都不是请求、装车或收货前置。** 原有工程可以继续供料或待工，救济不占用市政工程槽；不能要求先完成被缺供卡住的工程才能送粮。

首版只实现一份固定配方，根据申请时的真实载重确定：

| 申请时已有货车 | 固定送达物资 | 合计载重 |
| --- | --- | --- |
| 128 | 粮112、工具12、煤4 | 128 |
| 64 | 粮56、工具6、煤2 | 64 |

这些是**待真实原档试跑的初始配方**，尚无救济成功的实证。不要直接许诺一车就能恢复113人；每单只有表中有限物资。玩家可以在原车返抵后另签下一单，每次再次真实扣款；不自动生成永久补助或无限重发。当前铁轨药品充足，第一片不加第二种医药救济、自由货单编辑器或货币预算。

货物之外，home按 `CivilRegions.dispatchCost`实付原旅费：当前保存技术下旅粮1、木1，128车另付零件0.05。该费用不变成地方收入，不占货箱货物额度。派车须留下home现有120秒粮药和维护工具保护额，可复用 `CivilFinance.reserveCheck(s,'home',完整实际cost)`；这只是纯检查，付款由唯一救济事务入口执行。任一货物或保护量不足，原子零扣款、零车辆生成、零运单派发，不发空车或缩水包。

申请确定的cargo保持不变；若64车后来完成128改装，旧申请仍只运原64份，实际派车按当时车辆维护费支付。不能通过改装、切换节点或取消重签免费放大已付货物。

## 3 原车排程、交付与取消

每节点最多一张未结束救济申请，可与原市政工程并存。请求先排队，不预扣货物；在真实出发时一次支付完整cargo和旅费。已经运行的1875号贸易车、旧common订单、工程货车按原货单、原目标与原路程完成，救济不能抢占它们的在途状态或班组。

建议排程顺序：

1. 原车尚在去程、返程、候装、改装或断路等待时，救济等待。
2. 保留现有“非贸易之后必须贸易”的规则；不能因为请求救济就连续跳过所有普通贸易。
3. 轮到允许非贸易的空闲车位时，已明确请求的救济先于新common和新工程。只有这一张有限单生效，显示它会推迟下一笔预算或工程；旧Finance欠履约照实保留。
4. 救济返抵后不自动再排。下一非贸易车位若无新救济，恢复原common／工程优先序。

这使玩家能选择实际救急，而不会被每期重新到期的common一直排在后面。申请时若缺货，保持待补给及具体缺口，并阻止该申请静默降级成别的资本项目；玩家可以取消未派发申请，恢复原排程。

去程到达时，只有原shipment对象、合法订单身份、到期路程、原目标和可通道路同时匹配，才将cargo入 `regions.nodes[id].stores`。**直接进入地方原仓，不进入住房buffer，不直接增加健康或生产证据。** 接下来由原农作、医护、治疗和维护结算消耗。交付后同车空返，仍占原2工和90秒铁轨返程；无需地方另交粮、工具或返赠，不因当地健康0再次候装。

暂停与取消的含义必须区分：

| 操作或变化 | 最小行为 |
| --- | --- |
| 暂停路线 | 停止新派发，保留已付车辆及原申请；恢复沿用原ID，不生成补发 |
| 取消尚未派发申请 | 标记cancelled，未发生费用，无退款或货物收入 |
| 取消已派出、尚未交付救济 | 允许原车带未交付货物折返；按已走路程返回home，实际返仓才退cargo，旅费不退。需在Regions显式开放救济车的主动折返入口，不靠修改存档伪造held |
| 取消已经交付救济 | 不能收回已入地方仓的物资，也不能退home款；原空车继续返程 |
| 道路关闭 | 原车持货等待或按既有原路折返规则行动，不能穿越关闭路线直接到家；空返同样受路况限制 |
| 选择另一地方或改路 | 只影响下一张请求；已经申请／派发的target冻结。需要换目标时取消未发单后另签；旧在途不得改名转仓 |
| 运输工退休／死亡或被其他任务占用 | 继续使用Regions统一班组实际占用和移动规则；缺完整班组暂停，重新有实际人手后原车续行，不重付、不增加运输岗位 |
| 当地居民死亡、出生或人口变化 | 不按新人数重发或退款。目标节点及原仓仍合法时按原量交付；即使人口归零，也不会因此赠成人或恢复人口，后续请求需另行人工判断 |
| 当地关系改变或节点失效 | 未发单停止派发；已付且未交付货物保留，允许回原仓，不能静默丢弃或转送另一地 |

本片不建立运输工个人随车名册、不新增旅途死亡概率；沿用现有真实人口年更与岗位池，避免把新随机伤亡掺入救济修复。

## 4 最小状态与接口建议

建议新增 `content/relief.js`、`src/postwar/relief.js`及专属测试。配方属于content；`CivilRelief`拥有运单和唯一收付款，Regions继续拥有车辆、班组、道路、移动时间。不要令Regions通用credit和Relief.receive各入库一次。

```js
c.relief = {
  schema: 1, introducedAt, nextId: 1,
  orders: []
};
// order（仅建议）：
// id,target,requestedAt,requestedCapacity,cargo,status,
// shipmentId,dispatchedAt,dispatchCapacity,travel,paid,
// deliveredAt,returnedAt,cancelledAt,refundAt
// status: queued | outbound | empty | returning | complete | cancelled
```

pending仅引用正在查看的节点或订单，不能额外保存第二份cargo。queued阶段的实际付款和车辆字段应为空；派车时固定真实货车ID、派车容量、cargo、完整实付cost和travel；终态保留原始证据。无必要复制人口、健康、地方库存或每秒完整轨迹。

| API建议 | 责任与约束 |
| --- | --- |
| `init(s)` / `validate(s)` / `reset()` | 旧档无任何救济痕迹才可初始化空账；显式坏字段和孤立救济车辆拒绝。reset仅清模块展示引用 |
| `quote(s,id)` | 纯读节点、实际载重、配方、旅费、home保护量与缺口，不付款、不改排程 |
| `request(s,id)` / `cancel(s,orderId)` | 建一张有限queued申请；取消未派发单零支付。所有入口重查当前状态 |
| `nextCargo(s,id,capacity)` | 纯读当前queued固定货物与订单ID，供Regions选择下一允许车位 |
| `dispatch(s,p,cost)` | Regions放入候选原对象后，校验ID／原班组／路况／home储备，原子实扣、绑定订单；false须零变更，Regions撤销候选及ID |
| `receive(s,p)` | 唯一地方入仓点，原对象及真实到达时刻有效才入一次；随后Regions清cargo、改empty并开始原路返程 |
| `requestReturn(s,orderId)` | 只请求原车原路返航，不直接退款；Regions拥有折返距离与阶段切换 |
| `recordReturn(s,p)` | 空车返抵完成或未交付cargo返抵退款；只能一次。Regions仅在成功后释放原车辆／班组 |
| `validShipment(s,p)` | 双向核对订单、cargo、目标、实付和阶段；不递归调用Regions.validate |
| `event/refresh/nextEvent` | 原地区事件及状态行，所有点击重新quote／验证；不加经济settle或随机tick |

救济shipment建议新增 `purpose:'relief'`、`reliefOrderId`、`legStartedAt/legDuration`。原向去程和空返必须满足完整原travel；折返用实际已走距离。沿用Finance的实证经验：不能仅把remaining改0就收货，不能缩短legDuration加速到账，不能接受对象副本、孤立订单、重复receipt或两个运输任务抢同一路车。

读档必须双向核对：每个在途救济订单对应唯一shipment；每个relief shipment有合法原订单；终态不得仍占车，未派发不得有paid。缺整个relief但留purpose／订单ID痕迹时拒绝，不能补空账后放行。旧69初始化只增加完整空账，其他状态逐字不变；不从health0自动生成一次已付救济。

## 5 地方配工：使用真实折损，守住实际产能

救济到达后仍可能被错误的正常产率配工迅速耗尽，因此本片应同步修正Municipal的最小计算边界，而不修改基础产率或健康恢复速度。

建议提取纯 `outputFactor(s,id)`供 `planWorkers`和 `settleNode`共享，计算时机与当前结算一致：健康<30为0.75，结算开始时缺当轮口粮再乘0.65。农工需求循环应比较 `farmFood(候选人数)×当前factor`与真实口粮、医护／药剂粮耗、既有出口及必要小余量，不能只比较名义farmFood。当前原69有30农工容量和75成年劳动力，可在真实上限内多派已有成人；不能新建田片、复制人口或绕开实际岗位上限。

具体边界：

- 先满足粮食生产、实际诊疗及仍需维持的供水／供热，再按剩余成人安排其他岗位；每人只能占一个岗位。保留两名真实营建工的正常分配，施工仍须健康≥30及原工时。
- 工具、煤和废料不足时，配到岗位不等于成功产出；唯一生产run仍按现库存限制实际批次数、实扣投入，`paidInputs`与产出证据只记实际完成的部分。
- 计算本地供养和是否结束救济不能预算下一辆车尚未抵达的货物；一车到达只提高库存，不直接写“治疗正常”“净供养正”。
- 低健康下，制器工等其他产出也乘原实际factor。若以预计制器收入辅助配工，必须先受真实制器岗位、木／废料、劳动力和同轮生产顺序约束，不能把不存在的制器间产量算进去。
- 新生和年度粮费继续照原名册、真实储备与健康门槛处理；本片不调出生率、不回滚死亡、不为救济添加人口。

首轮实现先修“农工按同一真实factor计划”，不要顺带重做全部岗位优化器。若原69仍无法用有限救济恢复，报告实际每轮缺口与投入，而不是删除健康施工门槛、让农田免工具或把药品库存直接兑换健康。

## 6 原生UI与建议操作路径

在已知地方原地区事件内增加“筹办一车救济”按钮，显示本单货物、home实际支出、载重和等待的原车。危机提示可依据实际健康／粮食库存与连续实付供养，不能在未发现地区提前展示入口。可供查看申请、取消queued或要求未交付车辆返航；不新建救济页签和管理面板。

给下一轮主流程的建议步骤（尚未验收）：

1. 从原69原样加载，保持1×，让已付1875号贸易车继续原任务。
2. 申请铁轨128份救济，等待原货车和下一个允许非贸易车位；核对home真实扣粮112、工具12、煤4及原旅费，原车90秒去程。
3. 交付后观察下一真实生产边界的农工实际分配、工具付款、进食量与治疗付款；需要时在空返完成后再签一张，不自动填仓。
4. 健康恢复到30后，12号街坊按剩余真实材料和360施工秒完成。若材料未齐，救济与普通贸易之外的真实工程班次仍须继续；不要用救济cargo抵工程buffer。
5. 正常筹办地方制器间（木160、铁20、零件6，180秒）并实际运材施工；完成后确认已有成人开始实扣木／废料制工具。
6. 正常筹办回收场（木100、铁8、工具8，180秒），补上持续废料投入的实际岗位。停止申请新救济，验证独立粮食与工具链能够维持至少两个完整年度／1200秒，不将短期库存缓冲当长期净正。

建议先以最多6张128份救济作为测试预算：货物总上限粮672、工具72、煤24，外加每张实际旅费；未派出的不扣款。**这是验证上限，不是已证明的救济次数或自动申请规则。** 若6单内仍未恢复，应输出失败的健康、粮食、工具、班组和工期时间线，重新评估配方／派工，不能补填第7单或健康值让测试变绿。
