# 来源扩班与接纳教养约束

2026年11月1日本轮已实现的规则，以 `游戏/content/origins.js`、`游戏/src/postwar/origins.js` 和 `游戏/tests/origins.test.cjs` 为准。它修复河网接纳的教学瓶颈、一人批次名册错误，以及跨年出生占用旅客返乡床位的问题，不代表新来源、城市群或国家已经实现。

## 自然存档中的实际阻挡

原始证据是 `验证/存档/自然游玩_河谷首座住宅与三地学舍.json`，elapsed 为32462。河网已有2200人，健康100、饥饿0；累计迁出28人，协议还余1052。接纳暂停与河谷的48床无关：来源报价在核验目标住房之前已经失败。

| 来源条件 | 原存档／拟迁8人后的实际值 | 规则 |
| --- | --- | --- |
| 儿童与教师 | 原有822名儿童；迁走2名后仍820名，需要41名教师 | 原始教师岗位上限40，是唯一失败项 |
| 成年劳动力 | 原有1051人；迁居后1046人 | 剩余供养与教学计划需要450人，有余量 |
| 三段育龄留守 | 迁居后18—29岁274人、30—39岁221人、40—49岁227人 | 下限分别111、92、88人 |
| 来源食物 | 27734.40 | 迁居后120秒口粮约2762.88 |
| 来源药品 | 425.26 | 迁居后120秒药品263.04 |

固定40教师席并不造成这份存档永久灭绝。只推进原规则、不给任何物资、也不迁居时，儿童逐渐成年，到elapsed35400才会恢复报价，相距2938模拟秒，约4.9历史年。在4×速度下仍需约12.2现实分钟。百年来源推演还出现过另一段约7年的相同暂停。因此问题是没有扩班路径的固定教学上限，而不是目前的粮药、成人或育龄留守不足。该推演属于离线规则诊断，不是浏览器自然游玩记录。

## 来源用自己的材料和成人扩班

初始仍只有40个教师岗位。扩班不迁移人口、不更新原始1800人、不重置1080迁居额度，也不从炉火城取得材料。

- 当前真实儿童人数所需教师超过现有席位时，来源自动筹办一项扩班工程。
- 每次从来源独立仓库实付木料120、工具12、知识20；付款失败不留下半扣费用或工程。
- 来源保留正常农作、医疗、制器、回收、采木、现有教学岗位及联络人员后，还必须有2名实际空余成年建设者。
- 健康至少60、没有饥饿，并保留来源120秒粮药，才可以开工和继续施工。
- 工程需要180个实际工作的模拟秒。退休、缺粮药或健康不足会暂停剩余工期；原材料不退款，不补生成人，不靠加载存档推进。
- 完工新增10个教师岗位，即200名儿童的教学容量。最多7次，总上限110个教师岗位，恰可对应2200人来源住房的极限儿童数；实际教师仍受成年劳动力、教材木料和岗位分配约束。

没有建立第二份来源仓库或人口名册。建设者以 `sourceStaff` 预留在同一个成年劳动力账中；完工释放这2人，再按实际名册重排岗位。教学继续消耗每位教师每10秒0.1木料，报价也会检查下一轮教材投入，扩建本身不直接生成知识或替代在岗教师。

这次自然存档的规则克隆在32463自动实付开工，32643完工，新增一次扩班后有50席、42名实际教师，恢复8人报价。整个181秒过程包含启动后的180秒施工：home人口与仓库、来源2200人口、已迁28人、剩余额度1052均未改变。该结果是原始存档的离线规则复核；浏览器恢复接纳由主流程另行记录。

## 一人批次的名册修复

旧 `choose(...,1,'convoy')` 把“两名年轻成人”当成无条件下限，先选两人，随后用负的剩余名额继续抽取，可能形成总数为1、但其中含负人数的名册。现改为座位允许时才取两名年轻成人，一席只取一名实际成人；抽取循环只接受正的待取数量。

测试覆盖全部1—8席：每个年龄群人数为正整数，来源名册不被报价修改，迁出与留守按原cohort逐项守恒，并能提交后通过真实来源账校验。没有用“总数看似正确”代替原始名册守恒。

## 旅客的原住处保留到真实安置

旧规则只用“来源住房减来源现居人口”限制出生。来源满2200人时迁出8人，跨年出生就可能把人口补回2200；若目的地随后无法接纳，这8人真实返乡会使来源变成2208人，并导致下一次存档校验失败。

现在从同一份迁出回执派生返乡预留，不新建第二份人口账：

- `reservedBeds(s,id)` 是该来源所有 `status:'travel'` 回执的实际存活人数。去程、候床、带人返乡均保留原住处，暂停接纳也不会释放。
- `availableBeds(s,id)` 为 `max(0, housing - population - reservedBeds)`。年度出生在计算人数及支付粮药之前使用这个值，不能先出生再截断名册。
- 真实抵达其他聚落并成功登记后关闭回执，立即释放其原住处；空车返程不再占来源床位。
- Urban完成实际年龄推进并记入在途死亡时，只释放真实离世者的床位。重复死亡回执不能重复释放。
- 真实返乡把同一批在途居民并回来源名册，同时关闭迁出回执：预留转为居住，来源现居人口加在途人口的总和不变，不退旅费，不重建家庭，不吞掉回执。

现有每秒调用顺序先推进来源年度，再由Urban推进旅客年龄。因此某位旅客恰在这一年度离世时，来源的当年出生会先保守地保留其床位；实际死亡回执随后立即释放，下一年度才参与正常出生计算。不会倒放这一年的出生或补发生育，旅客也不会被两个模块各老化一次。

### 旧存档已经挤住的兼容

节点新增可选整数 `legacyHousingOverflow`，新来源为0。旧档只有字段缺失时，才登记当前 `max(0, population + reservedBeds - housing)`；不改任何居民、住房、仓库、出生或迁出历史。既兼容“源内2200人、在途8人”的返乡前快照，也兼容旧版已经把8人真实接回、源内2208人的快照。

迁移额度最多16人，对应既有两支8席旅队，且超额必须有合法在途或已返乡回执支撑；原有年龄名册、死亡、迁出身份、协议及人口恒等式仍必须逐项通过。没有迁出记录而单独增加出生或现居人数，不能取得这份历史宽限。显式null、负数、非整数、超过16或与实际挤压不符的字段不会被初始化自动修复。

这个字段只会下降。真实来源离世、在途离世或异地安置缓解挤压时，额度立即缩至实际剩余值；带人返乡只是把人从在途账移到现居账，不增不减额度。归零后永久保持0，后续出行不能再次借用旧额度。住房始终2200，出生也始终只按原住房减真实居住和在途预留计算。

例如旧档有2200人及8位未安置旅客，迁移登记8；这8人返乡后为2208人、额度仍8；随后若真实离世22人，只能付费出生14人，恢复2200人、额度归零。不存在免费的8床，也不删除已出生的8人。原有来源生产、口粮和医疗继续按实际2208人负担计算。

旧公路在来源文字中显示为未安置旅客保留的床数，以及尚未消退的住房挤缺；不新建住房面板。Origins提供的床位接口用于来源，Urban原有目的地床位接口保持不变。

## 状态、接口与读档

来源节点新增可选字段 `schooling`：

```js
{
  schema: 1,
  completed: [{ startedAt, completedAt, paid }],
  project: null // 或 { startedAt, lastWorkedAt, remaining, paid }
}
```

`completed` 是付费完工历史；教师容量由初始40加完工次数×10推导，没有另一份可以漂移的席位总数。`project` 同时保存实付材料与剩余工时；一秒内重复调用或读档重复tick不会多做一秒工程。

旧存档只有在 `schooling === undefined` 时补空历史与空工程，不回放过去扩班，不扣过去费用，不改出生、死亡、cohorts或仓库。显式null、错误工期、伪造费用、未来记录、超过7次的扩班记录会被拒绝。来源继续使用原schema1，缺字段的旧档先可通过校验，再进行幂等初始化。

对外查询如下：

- `schoolCapacity(s,id)`、`jobLimits(s,id)`：当前真实教师容量与动态岗位上限。
- `startSchool(s,id)`、`tickSchool(s,id)`：来源自付工程入口与实际施工；日常由Origins.tick自动调用。
- `quoteReason(s,id,maxPeople,{mode})`：成功返回null。失败在实际允许的候选批次中核验，区分联络、协议额度、年龄留守、教师席位、实际成人、粮药和教材；不修改状态。
- `schoolStatus(s,id)`：当前教师／席位、儿童需求，以及等待材料、等待成人或剩余施工秒数。
- `reservedBeds(s,id)`、`availableBeds(s,id)`：未完成安置者的来源原住处，以及当年出生可使用的真实空床；从迁出回执推导，纯查询不改状态。

旧公路原有来源文字显示这些状态。Urban使用报价原因解释无法发车，不另设学校管理面板，也不替玩家免费调整本地岗位或改政体。

## 验证边界

最新 `npm test` 的255项测试通过，其中Origins为30项。扩班与选人回归覆盖1—8席守恒、822儿童的准确阻挡、来源实付扩班、180秒工作、欠供与退休暂停、重复调用、费用与工期损坏、旧自然档只补零字段，以及有限110席上限。原有100年来源自养、育龄留守、迁居额度、死亡与返乡账仍通过。

本次另增5项返乡床位回归：满源迁出后使用真实Urban计时跨年、候床、返回；死亡仅释放实际1床；异地抵达释放原住处且空车不占床；旧档16人的挤压经抵达缩至8、死亡缩至7；旧档真实返乡后2208人完整导入；挤压归零后再次迁出不能复用额度。测试中的旧挤压快照按旧出生计算与真实付费重建，并非声称自然游玩曾出现这一状态。新字段为0的存档即使总人口账能闭合，也不能通过超额预留校验。

逐份只读复核现存13份含来源账的原始存档与测试fixture，均可先校验再初始化；除旧档确实缺失的目的地、扩班及历史挤压字段外，整份状态逐字保持一致，二次初始化不再变化。最新原始存档 `验证/存档/自然游玩_密集住区与河谷镇制.json` 为39046秒，来源2192人、在途8人，合计恰为2200，迁移后挤压为0。该复核未改写原存档；最终浏览器重载与页面床位文案由主流程另行验证。

这些规则测试及原始存档克隆复核不能代替新版本浏览器自然游玩，也不证明来源可在所有极端年龄或断供状态下自动恢复。无足够成人时，来源不会凭空建校；材料、留守与供养要求继续是真实限制。
