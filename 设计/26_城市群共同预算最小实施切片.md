## 1 本切片的终点与前置

保留设计16的规模：至少三座参与共同职责的城市，各有当前实际居民≥400，合计≥3000，连续600模拟秒通过完整检查。首版参与集合固定为home加玩家选定的两个地方节点；第四城、地方之间直接通车与全国财政留到以后。未参加协议的高地居民、三来源留守者、在途旅客和累计admitted一律不计入3000。

当前住房已经没有固定上限死锁。按设计24的home624、河谷600、铁轨620基础上限，各实建三座160床住区即可达3284床；每节点六座上限还留有余地。实际存档仍必须逐项付费、运材、施工和供水，不能直接把上限当已建容量。三来源与24人道路迁居已经可用，但完整年龄与生产模拟仍未证明自然三城达标。**没有证据需要降低400／3000／600门槛。** 铁路、货币、区域电网和某一种政体均不是本切片的硬前置。

共同预算应在扩成三城之前可试行：home曾登记city，已有两个正式地方镇制，各当前≥80、已同意市政且仍为associated或integrated；已研究records、administration、standards、logistics，四轴已经成立。读取真实行政容量与公共服务，不能先要求3000才能开始承担共同责任。两条路线已有真实贸易往返、可通行且有完整班组。初次选成员后不因界面换节点重定向合同。

## 2 最小预算：三仓互助，不建立合并公库

新增 `CivilFinance`，只保存合同、额度、实付凭据和履约摘要。home权威仓仍是 `State.stores`；地方仍是 `regions.nodes[id].stores`。不保存第二份库存、不产生金币／税收资源、不按人口发钱、不向Origins来源征调物资。

首版只提供一份“诊疗与道路互助”常设计划，不先做自由填数表单：

| 承诺／费用 | 确定值与实付时点 |
| --- | --- |
| 首次三方议约 | home知识30，两个地方各知识10；三仓同时足额才原子扣款，任一不足零变更 |
| 预算周期 | 600模拟秒；批准只是后续支出上限，不预扣整年物资 |
| home对每个地方 | 每周期至多一趟预算车，药品12、工具2；从home实际扣货，随原路线去程运输 |
| 每个地方对home | 同车抵达后，从地方实付木12作返程贡献；未备足时原车候装，不凭空回货 |
| 实际运输费用 | 仍用Regions.dispatchCost：木1、已有保存技术对应的旅粮1或2；128货车另耗零件0.05。一次出车支付一次 |
| 共同记录开支 | 中央统筹：home每10秒知识0.04；地方自治：home与两个地方各知识0.02。本项是新增合同的协调成本，与已有Society及档案馆费用分别记账 |

完整一周期的**转移量**为home送出药24、工具4，收到地方木24；地方分别收到药12、工具2并送出木12。转移不是全网生产或消费。两条预算车新增的实际旅粮／维护由home支付，路线运行时只认实际出车次数。没有付清的贡献保留为未履约状态，不让库存为负，也不自动形成可兑物资的债权。

这份小合同证明常设公共责任，不能替代三城各自的全部供养。药品抵达后入当地公共仓，原有医护和药剂、工具维护仍按原配方执行。预算模块归集这些**已经实际支付**的服务证据，不再扣一份药、不凭“预算通过”增加健康、教学、发电或水量。知识开支由Finance在每10秒真实结算入口扣一次；医护、水务、工业等仍由其原模块唯一支付。

公共服务覆盖所有实际居民，包括儿童、老人和变异居民；政治资格不改变口粮、治疗或教学人数。议约不吞并地方，不改其名册、仓库、设施所有者或原有权利登记。

## 3 保护地方底线，运输和未来承诺只算一次

home每笔新发货仍重查完整源仓储备：支付后至少保留120秒本地口粮与治疗药品，工具保留 `max(4, 最近实际每10秒维护需求×12)`。使用当前节点真实配给／加权人数和实际维护输入，不能拿全网余额替代。预算开支与货物有缺口时暂停新承诺；本地生产、单人恢复与既有回程继续。城市群成立时另要求300秒储备，见第6节。

地方返赠单独检查本次实际装走的资源及适用于该资源的本地保护额。本协议只装木12，木材没有额外固定留存量，因此地方至少有木12才实扣装车；木不足仍由原车候装。这次返程不支出当地粮、药、工具或煤，它们的短缺不能扣住唯一补给车。原始62号档已暴露旧“返赠也检查全部储备”的循环阻塞：铁轨工具不足4，木材虽充足却不能返赠，下一趟工具和工程材料因此也不能发出。此处替换旧规则，不削弱home新发货保护，不增发车辆、不免返赠、不清订单。迟到返抵可以完成原订单，但已经截止周期的欠履约历史保持原样。完整原档规则续跑见[共同预算返赠恢复_验收](../验证/共同预算返赠恢复_验收.md)，该续跑不是浏览器实玩记录。

每条地方路线仍只有原来一辆货车、原载重64或128、原路程60／90／120秒、原2名home运输工；去回程、候装与断路占用不变。新增 `purpose:'common'` 和合同／周期标识，不能另造“预算专车”。来源到目标的120秒接纳旅程依旧与这条物资路线不同。

预算车作为非贸易任务，遵守“非贸易之后必须贸易”。在允许非贸易的槽位中，已到期预算优先于新增工程；每周期每路线最多一趟，因此不会无限挤占施工。128改装、Services和Municipal仍用剩余真实班次。两条预算往返即使取最慢高地250秒完整循环，与一趟普通贸易交替也在600秒内；施工、断路或缺班组造成的延迟必须真实显示。

`common`去程实到后才计地方收入与lastSupplyAt；返程实到home才计home收入与履约。不要把启程、空车返程、预计收入或预算批准当最近到货。去程取消则原货随车回home；地方返程途中折返则原木回地方；收到的一方没有因随后停约自动退掉已经交付的物资。原路实际返回结束才释放车辆／班组。

共同出口必须并入未来开支，而不是只在发车时偶尔扣库存：home药24／工具4每600秒，地方木12每600秒。地方 `planWorkers` 的采木计划与资源余量应包括本地出口；home预测也要包含自己的费用。进口不预先当作本地产出，既有城市自养底线保留。

实施时统一Regions的路线承诺口径，避免“原贸易满频＋预算满频”重复使用同一辆车。无施工干扰的保守上限可令 `T=2×travel+10`，每600秒一趟common，占用原一个往返槽：每10秒普通贸易频率为 `10/T−10/600`，预算频率为 `10/600`。两者各乘自己的真实货物与dispatchCost，维护合计仍为原总班次频率；地方出口同样代入各自返程货物。施工材料只记实际资本支出，不当永久服务成本。实际扣款永远以真实shipment为准，预测不能发车或支付。

## 4 制度分别决定什么

| 制度维度 | 本切片采用的行为与代价 |
| --- | --- |
| 城邦／联盟／联邦／帝国 | 继续使用现有协调上限、公共记录与信任规则，不为预算另乘产出。城邦＋中央统筹容量2，一座实际在线档案馆即可增至4，足以覆盖home及两个城市；不能强制改联邦 |
| 中央统筹／地方自治 | 都要首次三方签约、保护当地底线。中央在已同意额度内统一排车，协调知识成本集中home；自治由各地持有固定额度授权，知识成本分散且总额更高。以后提高某地方额度／更换用途，中央需home承担修订记录，自治还需该地方重新同意并支付记录；本版只有固定互助计划，不提前做无限征调滑杆 |
| 惯例／成文宪章 | 不改变物资所有权。沿用既有改制费用与磨合；预算成员、用途或额度修订必须通过原生事件，成文宪章额外公示60模拟秒，等待期间旧已批准合同继续，不冻结既有旅队。点击时重查费用和成员状态 |
| 选举／任命／世袭 | 继续现有真实时间和交接。选举届满可产生一条预算述职事件，任命／世袭交接也能查看旧账；都不清合同、不退已花费用、不免欠供、不重发补助。未完成继任只暂停新的政治修订，已授权且可支付的日常合同继续 |
| 所有权 | **独立于四轴。首切片仍是各节点公共所有。** 去程货物交付后才从来源公共所有转为接收地公共所有；在途与原路退回绑定实际出资地。设“合作社／混合经营”选项必须以后真正新增owner、转交原料／岗位／产出去向与补偿账，当前不放仅加倍率的假所有制按钮 |

现有home的帝国／中央统筹产出修正只在home生产链应用；地方Municipal目前使用当地健康／饥饿系数。Finance不得把这些倍率再乘一次，也不得借新预算悄悄扩散到全部地方。政治制度不同不意味着同一批粮药可以被两套系统重复领取。

本切片修订操作先限于暂停、恢复、退出整个试行协议；退出停止未出发承诺，保留全部在途及历史。重新加入／改变成员需新的三方议约记录，不能以重签重置已付周期或领取货物。更高额度、采购优先级、合作社和私人市场明确属于后续，不以未实现选项冒充政治差异。

## 5 最小状态与唯一事务入口

已新增 `content/finance.js`、`src/postwar/finance.js`，分别拥有固定计划与合同账；`src/postwar/metro.js` 留待第二片。均不复制仓库、人口、运输队或电池。

```js
c.finance = {
  schema: 1, introducedAt, nextAgreement: 1, activeId: null,
  agreements: [], // id,members,plan,approvedAt,axes,approvals,paused,exitedAt
  periods: [], // id,agreementId,index,startedAt,endsAt,closedAt,routeOrders,paidAdmin,adminPayments,serviceTotals,lastObserved,missed
  orders: [], // 单一路线／周期与真实shipment绑定，记录实付、出发／到达／返程时点及状态
  receipts: [], // invoiceId,orderId,shipmentId,leg,source,target,cargo,paidAt,deliveredAt,returnedAt
  lastSettledAt: null, offered: false,
  revision: null // agreementId,action,requestedAt,charter,effectiveAt；请求时宪制决定0／60秒公示
};
c.metro = {schema:1,introducedAt,stableSeconds:0,lastObservedAt:null,formedAt:null,members:[]};
```

Finance接口已采用 `init/validate/nextEvent/event/refresh/reset`，以及 `quoteAgreement/approve/transportPlan/nextCargo/dispatch/receive/loadReturn/recordReturn/settle/observe`；`reserveCheck`保留完整发货储备检查，`contributionCheck`只检查返赠货物所含资源，两者均不付款。统一出口承诺位于Regions的 `committedFlow`，旧 `committedHomeFlow` 保留为wrapper。Metro的 `check/observe` 仍是后续设计。`quote`和`check`纯读；观察不回调经济结算；UI不通过切换全局State操作地方。

以 `agreementId:periodIndex:nodeId:direction` 为预算订单唯一键，同一订单只能绑定一个真实shipmentId；每路线每周期至多一次，不拆出多个免费返程。账上记录固定原数量、实际源／目标与已付维护，接收须绑定原对象、合法phase、remaining=0和路线可通行。重复调用、对象复制、跨来源换ID、读档重试都不得再次扣仓或入仓。历史回执不要求当前仓库仍有钱、道路仍开放或旧领袖仍活着。

实际服务证据由原所有者在生产后提供：`{nodeId,at,paidInputs,treatment,education,water,power,food,medicine}`。paidInputs记录实际消耗而非库存净差，区分建设、出口、生产维护和治疗，避免用“同时产10药、花10药，净0”冒充没有医疗成本。Finance每节点每at只归集一次；知识费用成功后才能写paidAdmin。不给模块绕过统一电力分配的接口，也不复用过期／已消费的供水凭证。

第一片的精确字段为`economy.paidInputs={at,resources:{...}}`，仅记录当轮已经实付的生产维护成本；`treatmentInputs`同结构记录实际治疗药费，地方`mealInputs`另记实际吃下的粮食，不能把欠供口粮需求当成实付。三者时间必须等于所属economy.at。旧档允许这些字段缺失，不倒推历史付款；发货保护在缺字段或证据过期时，用下一真实生产边界的克隆预测取得当前可支付维护证据，不能用净delta代替，也不能把未知视为零。口粮与治疗保留量仍按当前真实人口需求计算。

周期跨越时只结清当期真实记录。未发出份额记未履约，不批量补发跳过的年份；在途旧订单继续归原周期，下周期同路线先等原车返回。不能清旧订单腾出一辆新车。审批与船货所属周期不随现任领袖、当前选中节点或暂停按钮改变。周期摘要保存金额与凭据引用，避免每10秒追加完整仓库快照。

旧合法存档缺模块且没有任何共同预算痕迹时，仅初始化空账，introducedAt取当时elapsed，不回放过去预算／服务，不送粮药。显式null、错schema、伪造历史回执或有common货物却删掉finance都拒绝。“按字段是否存在”只决定Finance本体是否按旧档初始化，不能跳过跨模块证据检查：Regions无论finance字段是否存在，都必须检查所有`purpose:'common'`在途货物、共同预算订单标识与回执引用；有任一共同预算痕迹却没有合法Finance合同／订单，就拒绝导入，不能先补空账再把痕迹当旧档放行。完整导入在克隆上先验旧形状与跨模块引用、一次初始化、再验新结构，失败不改原档。原城乡名册、Services工程、Passenger快照和所有仓库逐字保留。

## 6 城市群观察：当前条件，不是三个历史旗标

每次真实10秒生产结束后，Metro取得同一生产边界的新证据；重复观察同一at不增加稳定度。三座成员必须同时满足：

1. 已登记city且当前各≥400，总实际定居人口≥3000；当前人口加该目的地预留床位不超已建容量。两个地方仍同意共同职责，原来源与在途人口不入总数。
2. 分别通过当前 `Urban.developmentReady(s,true)`／`Municipal.developmentReady(s,id,true)`：当期粮药净供养非负、真正治疗与教学、健康≥70、工业完整、实际机械生产用电≥4、污染<40和原工具40／铁40／零件20底线。不要只读取过去的city=true。
3. 各城有自己的实际供水覆盖当前居民；只看当轮已兑现服务，不把水站数量或过去水量当本轮供水。每节点发电≥本轮实际使用；本地多余电量不流向其他城。使用手动水务时按实际额外工人及300人半容量核验。
4. 各城至少300秒基本口粮、治疗药品和关键维护储备。口粮按当前配给需求计算，治疗药品为当前人口×0.01×30；工具／煤／零件／化学品按最近三轮及下一实际生产边界纯预测的必需输入最大值×30，建设和出口不算生产维护。年度出生与旅费另有真实预算，不能把同一储备同时许诺出口。
5. 两条必要路线各自通过真实 `serviceReady`，有完整班组、通路和近期实到；共用运力没有超占。普通贸易／施工／预算只从实际交付刷新相应到货证据，空车与预测不刷新。
