# 有限人口恢复最小切片：接口与当前边界

**状态：代码、回归与河网联络/议约/迁入的自然验收已完成。** 不将财政、电网、铁路、城市群或第二人口来源计入本轮完成项。此前 `7cef800` 检查点的450人首城与第六任领袖，是旧版自然路径证据；不能用它代替本切片的自然验收。

本轮只增加一个永久的外部社会“河网散居圈”。旧480名册枯竭或高龄后，哪怕 home 已没有成年劳动力，也可以由来源自己的人员建立联系，随后用手动采集取得的真实食物逐人接纳。联系本身不赠人口，迁入必须从来源年龄名册扣除。

## 1 当前范围

新增 `content/origins.js`、`src/postwar/origins.js`、`tests/origins.test.cjs`，运行对象为 `CivilOrigins`，状态为 `c.origins`。来源既不是附送的城市，也不是 regions 加盟节点；其粮药、设施与工作人员都不能直接变成 home 的可用资源。

Urban 继续独占接纳队列与全局 `nextParty`：批次最多8人，每人6粮、0.2药、0.2工具，2名运输工，去程120秒、回程120秒，所有来源合计最多两组。床位、真实药品供给、儿童教学和120秒口粮仍由 Urban 校验；运输工由 Regions 与 Urban 共用一个池。Origins 不创建第二套接纳车队。

本轮已抽出 `CivilPopulation`，home、来源与地区邻居已接入其年龄/生育计算。沿用18–49岁育龄人口8%的年度期望、年初人口4%向上取整上限，每孩实际支付6粮与0.2药，欠缺的整数出生不积压补发。来源为1800人的既有社会，直接使用比例模式；各模块仍各自负责库存付款、名册提交与时钟，不能共同推进同一批人的年龄。

## 2 恢复路径及真实费用

已知河谷（旧 `village.riverKnown` 或新 river 节点），或旧 Urban 名册已登记，就能在旧公路看到“沿河网联络”。不要求本地知识、工具、成年探访员、车队场、正式镇制或城市。旧来源为空或其18–49岁人数少于16时写一次提醒；联系也可以提前主动进行。

联络由来源社会的2名真实成年工作人员承担，来源一次支付12粮与1工具，持续240模拟秒。出发前必须在来源基本供养岗位之外还有这2人；行程中保留其岗位占用，`reservedLabor(s)` 对 home 恒为0。来源人口口粮继续统一由其本地经济负担，旅粮是额外费用，不从 home 扣人口或补给。只有一次未完成行程，不允许平行重发；完成后永久进入 contacted。

contacted 即允许逐人到访：每人实际支付 home 6粮，保留来者真实年龄与身份，来源至少保留720人、分年龄带育龄底线及自供岗位。此路径不要求 home 有成年劳动力、知识或工具，也不占批次运输工。Home 的床位、温暖、饥饿和已有居民信任条件仍由既有到访入口处理；它是按原有节奏执行的恢复路径，不是点击就无限生成成年人的按钮。

批次接纳另需一次20知识的登记协议。支付后状态为 agreed；重复确认不会重扣或刷新额度。协议只开放迁居，不转移来源的土地、库存或政治主权。来源由玩家用原生按钮选择 `urban.activeSource`，没有选择时仍用 dispersed；切换只影响下一次到访/发车，不改已经在路上的人。

## 3 一次性基线和真实供养

河网基线1800人、2200床。首次接入此功能时创建0至79岁混合名册：0–39岁每岁23人，40–79岁每岁22人，含人类与变异居民，共160个有稳定 `cohortId` 的组。基线是此前未建模的外部既有社会，不计入 home 的出生或接纳。`introducedAt` 与初始世界年记录一次；尚未联系也照常结算来源生活，读档、访问、换任都不刷新年龄或人口。

每10秒来源经济只修改自己的库存、岗位和健康，返回 home flow 为 `{}`。预判在克隆中运行也不能领取来源资源，不能通知玩家或写全局 State。按现有成年劳动力分配以下实际岗位：

| 岗位 | 每人每10秒投入 → 产出 | 岗位上限 |
| --- | --- | --- |
| 农作 | 工具0.01 → 食物1.4 | 320 |
| 医护 | 食物0.2、废料0.1 → 药品0.15 | 180 |
| 制器 | 木料0.2、废料0.6 → 工具0.25 | 16 |
| 回收 | 劳动 → 废料0.8 | 40 |
| 教学 | 木料0.1 → 知识0.2；每人覆盖20儿童 | 40 |
| 采木 | 劳动 → 木料1 | 20 |

农业岗位按实际口粮与医护食物倒推，并留15%生产余量；医护目标 `ceil(人口×0.01/0.15)+2`，制器/回收/采木按投入倒推。实际岗位不超过人数和设施，缺料仅运行付得起的批次。口粮每10秒为加权人口×0.12，儿童权重2/3；治疗为实际人口×0.01药。缺粮降低健康与生产，出生也受住房、至少6劳力、至少2育龄者、健康60、无饥饿与真实粮药约束。

来源首次缓冲为12轮口粮加1000粮、12轮治疗加50药、120工具、300废料、200木；它只属于外部社会且只初始化一次。食物/药品仓容各为120轮需求，另有最低小仓容；工具上限5000，其余基础物资10000。多余物资记入 discarded，不转给 home。年度先老化，80岁离世记账，再实付出生，孩子以 age0 加入名册。

## 4 有限额度和育龄留守

同一来源累计允许迁入边界最多1080人：已抵达 home＋在途存活＋途中死亡不得超过1080。来源至少留下720人；来源出生、读档、新领袖、再次协商都不刷新协议。未定居而活着返回的人恢复相应名额，旅费不退；到达 home 后的死亡不恢复旧额度。

除总人口外，保护三个育龄带的初始40%（向上取整）：18–29岁至少111人、30–39岁至少92人、40–49岁至少88人，共291名育龄者。还要留下足够的成年农业/诊疗/制器等岗位，并保留12轮口粮与治疗库存；来源健康低于60或饥饿时暂停迁出。随着真实年更，某一年龄带不足会暂停报价，等待下一代长大；不补发成年人。

逐人到访从富余的育龄带取真实成人，保护上述底线。初始时连续即时抽取的实际上限为435人，不能把1080总协议当作1080名即时可用年轻人。之后下一代长大可继续占用尚余额度。

批次尽量包含5名成年人、2名儿童、1名65岁以上老人，其中至少2名18–49岁成人，其余成人优先由50–64岁实际居民补足；缺少某类时用真实剩余成年名额或缩小批次。相同 cohortId 的多次选择合并为一条，不制造重复名册记录。这仅是年龄混合小组，未实现婚配或家庭关系，不声称识别亲属。变异身份不改变迁入费用和基本服务权利。

自动化实测：混合批次可兑现全1080人，留下720名真实居民；逐人提取435后或批次提取1080后，来源再结算100年，都保有成年劳动力、真实出生与死亡、健康至少60且无饥饿，额度不刷新。另测初始来源在未联系状态生活100年后仍可联系与迁入，其原初年龄组已经自然离世，存活者是实际出生的后代。

## 5 接口合同

```js
CivilOrigins.init(s)                      // 仅 origins===undefined 时创建一次
CivilOrigins.discoverable(s)
CivilOrigins.beginContact(s)              // 源付12粮1工具、源2值守、240秒
CivilOrigins.reservedLabor(s)             // home占用恒为0
CivilOrigins.sourceStaff(s, originId)     // 本源行程占用，0或2
CivilOrigins.agree(s, originId)            // home实付20知识，一次性
CivilOrigins.quoteParty(s, originId, maxPeople, {mode:'singleton'|'convoy'})
CivilOrigins.commitDeparture(s, quote, partyId) // boolean；仅扣来源
CivilOrigins.recordArrival(s, party)      // boolean；首次成功记账，不加home居民
CivilOrigins.returnPeople(s, party)       // boolean；首次成功归原年龄名册
CivilOrigins.recordTransitDeath(s, party, count) // boolean；年界死亡回执
CivilOrigins.remaining(s, originId)
CivilOrigins.settle(s)                    // 每10秒来源经济，home flow={}
CivilOrigins.tick(s)                      // 每秒联络/来源年更；不推进旅客
CivilOrigins.validate(s)
CivilOrigins.refresh()/reset()/event(id, done)/nextEvent(s)
// pendingIds = ['originContact','originAgreement']
```

报价是无副作用的 `{originId,revision,mode,cohorts,count,cost}`。Urban 先完成住房/服务/运输等检查并支付 home 旅费，再使用全局 nextParty 调 commit。commit 核对版本、重新报价及实际年龄组；失败则 Urban 返还本次付款。Origins 不自行扣 home 旅费，也不自行向 home 追加人口。

逐人事务为“quote → home付6粮 → commit → 临时 party → recordArrival → 追加home年龄组”；成功后没有零时长队列项。批次保存真实 party，到达后第一次 recordArrival 成功才追加 home 名册，清空乘员并保留空车返程。返乡调用 returnPeople，活着的组只归回原 source。

Urban 是所有途中乘员的唯一年更者：先 `aged = CivilPopulation.age(party.cohorts)`，在 party 仍保留跨年前数组时调用 `recordTransitDeath(s, party, aged.deceased)`，再赋 `party.cohorts=aged.cohorts`。Origins 用同一纯函数验证计数，以 partyId＋Urban.year 记回执；同年重复无效，不会阻挡下一年的相同死亡数。来源自己的 annual 不碰在途乘员。

## 6 状态与守恒校验

`c.origins.schema=1` 保存 introducedAt、唯一 contactTrip、warned 与 nodes.river_network。节点含 status（unknown/contacting/contacted/agreed）、baselinePopulation、当前 year、revision、cohorts、population、housing、stores、workers、health、hunger、births、born、sourceDeaths、transitDeaths、admitted、permit、departures、announced、discarded。

每条 departure 用 `p<全局partyId>` 作键，保存 partyId、mode、status（travel/arrived/returned）、initial、alive、dead、原始 cohorts、startedYear、closedYear、deathsByYear。原始名册不随旅客年更变化，以此核验合法年龄与死亡回执。所有持久节点 year 必须等于存档世界年，过期年份不能导入后重演出生。

每来源必须满足：

`1800＋实际出生＝当前来源人口＋在途存活＋累计抵达home＋来源死亡＋途中死亡`。

arrived 是累计离开来源的流量，home 后续死亡仍保留该累计数；计算现存全网人口时不能再次相加。

来源与 Urban 双向校验：每个 travel 必须唯一对应相同 source/id 的实际队伍，包含0乘员的队伍；当前年龄、身份、cohortId、人数必须等于原始组按经过年份推得的幸存组。每个新源 party 也必须有 departure。arrived 只允许仍存在的空车 returning 或已经完全离队；returned 不得仍在队列。partyId 必须小于 Urban.nextParty。逐人已抵达没有持久 party 是合法状态。显式 null/false、负库存、重复组、错误总账、旧年份或伪造旅客均拒绝，不能重新初始化“修好”。

## 7 旧档接入和保持事项

本轮 Urban 内部 schema 仍为1，新增可选 activeSource；不采用草案旧提议的 selectedOrigin/schema2。旧 source、admitted、deceased、year、nextParty、正在行进的年龄组、剩余时间与口粮均保持原值。新来源人数不并入旧480总账：

`旧source剩余＋dispersed在途存活＋u.admitted＋u.deceased＝registered ? 480 : 0`。

只有不存在 origins 字段的旧状态可初始化外部基线。已有 origins 的局部损坏必须拒绝。本轮全局存档 envelope 保持 version1 兼容；正常UI重载或重复导入同一完整存档不会刷新基线。单靠可缺省字段无法区分真正旧档和人为删除整个 origins 后的新档，本轮不处理这种手工删改/降级存档的防作弊，也不声称防任意篡改。全局升版与统一迁移留到节点经济整合阶段。完整旧备份可以恢复到它自己的历史，不得混用旧来源账与新增 home 人口。

旧home比例生育 credit、名册、领袖和既有资源保持；首次接入只新增外部社会账，不能增加 home 人口、床、设施、物资或科技。

## 8 UI、验证和后续边界

沿用ADR原生旧公路、按钮、事件窗、左侧通知与右侧 home 库存。Origins 只显示联络/议约与来源信息；源选择归 Urban，standards 后沿用街区入口。未知第二、第三来源不显示空按钮。不为每次来源生产刷日志，不把外部仓库混进右侧可花费库存。

目前 Origins 15项专项回归覆盖：一次性基线与无home副作用、源值守与实费联络、零成年可报价、一次性议约、只读报价与原子失败、抵达/返乡幂等、无持久party的逐人到访、按旧年龄回调的跨年死亡、同一party不同年度相同死亡数、0人旅队仍须在途记录、伪造年龄/身份/队伍的导入拒绝、成人补位组去重、旧年份拒绝、两种有限抽取后100年自供、未联系来源100年后恢复。Urban 独立集成回归另覆盖实际 home 6粮接纳、两来源共享运力、带人返回和79岁来源旅客跨年后其余居民正常抵达。

自然检查点已保存为“自然游玩_河网迁入与在途名册.json”与natural-origin-migration fixture：508本地人、来源1816人、累计河网抵达12、在途8；原样重载后同批居民继续抵达。自然流程没有将本地人为清空，零成年恢复与100年来源自持仍为规则回归。全套152测试通过。后续3000人城市群仍需扩大住房/公共服务、真实成长的地方节点及额外永久来源；本次仅河网1800、累计迁出1080，旧城外缘/山间聚居圈5400等均未实现。扩展时复用同一来源ID账本规范、Urban队列和CivilPopulation，不能提高旧480或反复重置河网冒充新人口。
