# 城市供养与接纳实装规则

**地方接纳扩展：** `activeTarget` 缺失默认home，原生街区的“接纳目的地”仅在地方市政议约后出现。仅后续批次切换目的地；逐人恢复仍到home，已发车target不改。home实付旅费并保留自己的120秒口粮，目标地方必须另有实际床、120秒粮、田片/诊疗/学舍和可持续供养；两地储备不可相互代用。途中、等床和返乡均占同一两组交通岗位，断路不瞬移。来源凭据绑定target，真实到达只加入目的地名册。地方80/400判定归Municipal，home首城人口不混入邻居或途中人员。当前完整规则见设计18，189项测试与自然进度见设计08最新节；下面保留首城实现记录。

本说明记录本轮已经落盘的 `CivilUrban`，以 `游戏/content/urban.js`、`游戏/src/postwar/urban.js`、`游戏/tests/urban.test.cjs` 及其共享接线为准。设计13是原始实施规格；出现字段、门槛或行为差异时，先按本说明理解当前版本，再决定后续调整。地区贸易、共同工程、加盟与公民资格另见设计14。

当前已实现公共服务扩容、两级城市住房、有限来源人口的接纳队列、80人正式镇制与400人首城条件。自然实玩已经登记首城“炉火城”，保存450本地居民、第六任领袖的原样存档。连续300秒的实际粮药、教学、工业供电、行政与邻地公共工程条件均已走通；当前152项测试覆盖规则和各阶段存档；河网来源扩展另见设计17。92人与246人仍保留为中途检查点，`natural-first-power.json`是更早的44人供电基线。规则测试与自然证据分别列在第11节。

## 1 模块边界与接口

人口与城市进度放在 `civilization.urban`，不是设计13草案中的 `civilization.regions.migration/chartered/city`。本地居民始终使用 `game.population`、`game.workers` 与 `society.cohorts`；远方城镇仍由Regions持有独立名册和仓库。接纳来源不是第四个经营节点。

| 接口 | 当前职责 |
| --- | --- |
| `init(s)` | 仅在urban字段缺失时创建schema1空状态；不发人口、资源或建筑 |
| `settle(s,{flow,deltas})` | 每10模拟秒在全链经济之后接收本轮真实证据，扣减已预付的在途旅粮记录，累计镇制/城市稳定度；返回home flow，目前为空对象，不再次结算生产 |
| `tick(s)` | 每模拟秒推进来源/在途年份、旅程、候床、返程与自动发车；返回人口/库存是否改变 |
| `handleArrival(s)` | 接管旧每60秒到访入口；未登记返回false，登记后或主动选择已联系新来源后始终返回true，实际不能接纳时也不放行旧入口另生人口 |
| `reservedBeds(s)/availableBeds(s)` | 计算在途及候床住房承诺，以及出生、单人到访、批次发车共用的可用床位 |
| `reservedTransport(s)` | 仅计算本模块旅队及回程班组占用，不计算地区路线 |
| `forecast(s,cohorts)` | 在深克隆上加入拟接纳居民，运行同一份经济规则；返回copy、flow、deltas，不动权威状态 |
| `register/dispatch/returnParty` | 名册单次登记、原子付费发车、带人返回来源的状态转换 |
| `nextEvent/event/pendingIds` | 条件事件与原生事件定义；不在done回调中串写下一pending |
| `refresh/reset` | ADR“街区”地点、建设按钮、设施计数、接纳安排与重开引用清理 |
| `validate(s)` | 检查schema、名册账本、旅队唯一编号、年龄、阶段、年份与建制待办 |

`pendingIds` 是 `urban_register`、`urban_charter`、`urban_city`。Urban没有新增探索旅程；接纳旅队使用独立的持久队列，不占旧 `c.journey`。

共享接线的10秒顺序为 Rules → Village → Society → Industry → Regions → Origins → Urban。adapter在最前保存本地库存，最后将完整home flow和真实库存差额交给Urban；其中 `诊所治疗.medicine` 是本轮实际支付的负数。Urban不能在药已扣除后再问一次“还能不能支付治疗”，否则刚好完成本轮治疗的聚落会被误判。

每秒先处理Society的年龄/出生，再处理Regions、Origins来源和Urban旅队；完成名册、人口、物资变化后，adapter更新原生居民、库存和收入显示。旧到访与出生已经调用共用床位接口。建造按钮、实际建造和存档校验共用 `CivilCatalog.buildingLimit(s,id)`；农夫生产使用统一 `jobCapacity`，新田片不会再被旧16农夫上限截断。

## 2 数据、迁移与账本

urban主要字段如下：

```js
{
  schema: 1,
  registered: false, enabled: false,
  source: [], parties: [], nextParty: 1,
  admitted: 0, deceased: 0,
  year: Math.floor(c.elapsed / 600),
  dispatchClock: 0, status: '等待地区名册',
  chartered: false, city: false,
  townStable: 0, cityStable: 0, economy: null
}
```

年龄组保存 `{age,count,identity}`，identity为human或mutant，与地区名册一致。旅队保存唯一id、source为`dispersed`或已联系来源id、target=`home`、state、remaining、heldFor、cohorts和rations。state是outbound、held、returning或returning_people；不另外保存一份可漂移的“预留床位”计数，直接由真实旅队计算。

旧档完全没有urban字段时，导入后初始化空模块。显式 `null/false/0`、错误schema或坏账本均是损坏，不通过初始化补成新档；读取失败不能补发480人。已登记名册在读档、重进事件、继任或改制时均不重建。

登记后，迁徙来源账本恒为：

`旧来源剩余人数 + source=dispersed的在途旅队人数 + admitted + deceased = 480`

`admitted` 只累计从旧dispersed名册移交本地的人数；新来源的抵达/死亡另由Origins记账。它不是当前本地存活人口；`deceased` 只记录仍在来源或旅途中达到80岁的离世者。迁入后的出生、衰老、离世和饥饿离开由Society及既有聚落逻辑负责，不能再从来源重复扣一次。本地原有居民与新生儿也不算进这480人。

这是一份年龄组及迁徙阶段账本，尚不是逐人的亲属谱系或可反查终身经历的唯一居民ID系统。旅队编号唯一；每人没有单独编号。

## 3 来源名册的具体人口

已发现至少两个居民邻居后，原生事件“沿路的名册”允许登记。发现计数由 `CivilRegions.discoveredCount` 提供，尚未迁移的已知河谷也算一个。选择登记不会立即增加本地人口，也不会自动启用批次接纳。

一次创建60组、每组8人，共480人：

| 每组组成 | 初始年龄 | 人数合计 | 身份安排 |
| --- | --- | --- | --- |
| 四名成人 | 24–39岁 | 240 | human |
| 一名成人 | 25–38岁 | 60 | mutant |
| 两名儿童 | 5–12岁 | 120 | 每三组中一组为mutant，其余human |
| 一名年长居民 | 60–67岁 | 60 | 每四组中一组为mutant，其余human |

总计human 365人、mutant 115人。这里“年长”不等于全部退休：统一退休界限为65岁，因此初始名册实际上有339名18–64岁可工作者、120名儿童、21名退休者。每个完整8人组有5名较年轻成人、2名儿童、1名年长居民；不足8人的最后一批或零星来访会按名册顺序取实际年龄组，不保证每批都恰好是这个比例。

来源居民不吃本地口粮，不产本地资源，不能分派进本地岗位。来源和在途人员每600模拟秒也长一岁；达到80岁计入deceased并离开其原队列。不会因读档再次过生日，也不会以同龄新人补满名册。来源不进行出生；它不是无限人口生成器。

抵达时先把原cohorts与population一起写入，再调用 `CivilSociety.sync`，避免先增加总人口被sync补成一批无龄成年人。identity继续留在本地年龄组中，变异身份没有额外生产惩罚。登记承诺相同的基本口粮、诊疗和儿童教育；这不替代Regions中另行议定的政治代表与公民资格。

## 5 发车、住房预留与共用运输

启用“安排批次接纳”后，最多同时有两组旅队。每批最多8人，实际人数还受空床和来源余额限制。每组需要2名可用transporter，车队场cartdepot与logistics已具备；运输岗位与地区合同用同一个池，不能各自取得全额人数。

`CivilRegions.availableTransport` 从实际运输岗位及建筑容量扣除地区路线班组和Urban旅队班组。Urban的outbound、held、载客返程、空车返程都占2人。运输工退休或改岗后，已经付费出发的旅队继续；新的发车等实际岗位恢复。没有用“暂停接纳”释放一辆仍在路上的车队。

发车按每人6粮、0.2药品、0.2工具一次付清，所有检查通过后才同时扣物资、从来源取人、创建旅队。检查失败不扣部分资源、不先挪走居民。完整8人批次就是48粮、1.6药、1.6工具。

额外条件包括无饥饿、健康至少60，公共诊疗站/学舍有实际岗位；把其他已在途居民和本批人一起纳入后，药品生产扣本地治疗及贸易负担仍不为负，所有儿童有真实教学容量，公共行政能支付。发车后库存还须覆盖全部预计居民120秒的口粮。

120秒口粮公式是12轮×有效食物人口×0.12×口粮政策系数×蓄水池系数；儿童按2/3成人计算，有蓄水池系数0.9。这里检查的是发车当时的储备，并没有另开锁定仓；之后玩家继续建设、研究或改变岗位，仍可能让本地短粮。发车也没有要求本地粮食净产量已经为正，能够用有限储粮接纳；正式建制另有持续净供养门槛。

来源扣人后只在旅队中占有；到达前不计本地居民和劳动力，但预留相应床位。可用床位恒为 `max(0,住房容量−本地人口−outbound/held载客数)`，同一个值约束出生、旧到访接管和下一批发车。

单程120秒，成功安置后空车返回120秒。成功发车间隔120秒，失败每10秒重试；两组错峰运行。保持全部条件的理想路径约每120秒增加8名本地居民，实际还受到建设、死亡、年龄结构、停运和资金影响，不以这个算式替代实玩时长。

旅途中rations来自已经扣除的每人6粮，每10秒按每名乘客0.12消耗；当前旅途不再按儿童或口粮政策折算。安置或返回后未用完的预付旅费不退成本地资源。抵达时目前只重新检查住房，没有重复执行整套发车医疗/口粮检查。

如住房不足，旅队在接纳点held，仍保留居民和预付补给。住房恢复就安置；候床达到120秒或旅粮耗尽则自动带人返回，返程120秒后把原年龄组放回来源。带人返程时释放目的地床位承诺，但继续占运输班组。已有 `returnParty(s,id)` 接口，本轮UI没有单独的“召回指定旅队”按钮；自动候床/返还路径已经运行。不存在静默删掉无床居民或同时把他们留在来源与本地的操作。

## 6 低速来访、暂停与有限恢复

名册登记后，旧每60秒到访完全交给 `handleArrival`，不论批次计划是否启用。可以两种速度都运行，但都从同一份来源扣人；不会额外由旧无限到访再生成第二批人。

低速接纳每次最多1人，需要实际空床、温度至少2、无饥饿、6粮；本地有人时信任至少15。6粮实际扣除。它不要求工具、药品、车队场或批次服务检查，因此药品/工具暂时耗尽时，可暂停大批接纳，保留低速恢复。接来的仍是名单上那个人，可能是儿童或退休者，不能为了恢复劳动力偷偷换成成人。即使本地为0人，登记后的入口也只接纳1人，不复用原来的“初次两位拾荒者”。

常规短缺有具体恢复路径：

- 缺药：先暂停接纳或地区合同，追加诊疗设施和实际医护，并供给食物、废料；研究/建筑本身不产免费药。
- 缺粮：恢复泵站木料/食物维护，增田片与农夫，减少继续迁入；本地农业容量可承担首城基本口粮，进口只提供余量。
- 缺工具或零件：已有制器和手动机械生产能继续运行；扩建制器间和岗位，积累实际材料。
- 缺运力：等待空车返回、停发无在途合同，或补充真实运输岗位；既有在途人和货不被抹掉。
- 缺床：先停迁入、付费扩建；已经在途的旅队候床或返回，不用删居民让校验通过。
- 供养跌落：当前建制稳定计时归零，恢复后重新累计；已获得的镇制/城市称谓和房屋保留。

恢复是有限资源规则，不是永久重生承诺。原先全聚落固定每年最多出生1人，配合80岁离世和有限480人来源，会使长期人口最终受约80人稳态限制，永久挡住400人门槛；因此本轮追加了下节的真实育龄比例出生。来源本身没有补充或出生，来源/在途也会老死。如果来源耗尽且本地无人，或已无育龄人口与可成长的孩子，仍不会凭空产生成年人或补满来源。来源只余儿童、老人时也不保证立即补足劳动者。修复的是正常供养与年龄结构下的长期增长规则，不能宣称任何断供或同龄孤立群体都不会灭绝。

## 7 育龄比例出生与长期恢复

出生继续由 `CivilSociety` 管理，Urban只提供真实床位与接纳承诺。每600模拟秒先让已有居民长一岁、记录80岁离世，再产生age0新生儿；新生儿要实际经历18次年更才能工作，不能用人口总数直接增加成年岗位。

Society schema仍为1，新增 `births:{scaled:false,credit:0,mutantCredit:0}`。旧档没有该字段时只初始化零余数，不补生过去若干年；字段存在但损坏则拒绝导入。三个字段会随存档保存，不在继任、改制或读档时清零重算。

满足任一发展条件就永久启用scaled：本地曾达到80人、已经登记正式镇制，或者掌握standards并建成公共诊疗站与公共学舍。第三项检查设施存在，不要求此时配员；实际能否出生仍受下列供养和劳动力条件约束。每秒及年度更新都会保留这个阶段，年度判断发生在年老离世之前，所以不会落入“年初80→离世1人变79→旧规则生1人回80”的永久停滞。

| 阶段 | 每年的期望数量 | 共同限制 |
| --- | --- | --- |
| 尚未启用scaled | 最多1名 | 真实18–49岁育龄居民至少2人、18–64岁劳动力至少6人、健康至少60、无饥饿、有未预留空床、实际支付粮药 |
| 已启用scaled | `floor(本年实际育龄人数×0.08 + credit)`，再限制为不超过 `ceil(年初人口×0.04)` | 同上；不按所有成年人或总人口直接计算出生，不把老人算进育龄 |

每名新生儿实际消耗6粮与0.2药品，包括早期最多1名的阶段。年度最终出生人数还受实际床位、可支付粮食和药品整数份数限制。不能只因理论期望有若干孩子就先加人口后形成负库存。新生后还需继续承担儿童口粮、教学和18年的成长时间。

credit只保留不足1人的小数，未获出生的整数不构成未来欠账。健康、饥饿、育龄人数、劳动力、床位或一份粮药不足时清除出生credit；部分数量能够支付时只生能支付的部分，并清掉本轮未完成的出生余数。恢复住房或物资后不会把数十年没有出生的孩子一口气补出来。满床时也不能预支在途家庭已经保留的床。

新生儿按真实育龄居民中的mutant比例分配identity，用mutantCredit保存不足一名的身份分配余数；未记录identity的旧居民视为human。只有年长变异居民、却没有变异育龄者时，不会以全体人口的身份比例生成变异新生儿；没有变异育龄者会清掉该身份余数。它是人口登记的抽象继承规则，不是完整亲子关系、两性配对或变异基因模拟，也没有给不同identity设置产率或生育率惩罚。

这个比例高于固定1名的长期替代上限，同时用4%年初人口上限限制一大批年轻迁入者刚到时的婴儿数量。以年龄0至79岁各1人、总80人、624床、持续供养充足的纯年龄模型为例，8%育龄年率约70年可通过真实出生与成长达到400；它不是70年后免费发320人，更不是自然实玩时长承诺。正常首城仍可由有限来源接纳与本地出生并行到达。

另一次独立年龄探针使用natural-first-power的真实44人年龄、原480人来源分布、每年最多50人从来源移入、624床、每年真实衰老/80岁离世，并按相同8%与4%限制推算300年；第30年后的最低人口为544（第56年），说明该正常年龄路径不再必然滑落到400以下。该探针把供养设为充足，没有模拟玩家购买设施、岗位不足或贸易中断，因此只证明人口规则有持续恢复空间，不能替代实际游戏经济和自然实玩验收。

## 8 真实经济证据与80／400门槛

每次真实10秒结算记录一个economy快照：时刻、粮/药净供养、实际治疗、实际教学、工业链是否运行、生产设施实际用电。它不是库存瞬时截图，也不是12轮滚动平均。连续每轮满足才累计10秒，失败归零；事件确认还检查证据没有超过10秒且当前人数、库存和环境仍符合。

粮药余量使用本轮实际home库存差额，再扣 `CivilRegions.committedHomeFlow` 的每10秒平均合同出口/旅粮。不计预期进口。在当前接线中地区发车、到货发生在tick，地区settle只做经济，因此这个口径不会把同一趟真实发车再从settle差额扣第二次。接纳出发费也是tick中的一次费用，不作为永久生产负担，但已减掉真实库存，仍会影响120秒储备检查。

本轮实际医护产量必须覆盖人口×0.01药品，并确实支付本轮治疗；仓库已有药不能替代当前制药能力。实际教学必须覆盖全部本地儿童。城市本地粮药余量非负是硬门槛，不依赖每次尚未抵达的进口包。

正式镇制要求连续180秒满足：本地至少80人且住房未超额；公共诊疗站和学舍有岗位；健康至少60、无饥饿；上述粮药净供养、真实治疗、教学和Society公共行政正常；至少一条当前正常往返路线。路线通过Regions的tradeReady判断启用、道路通行、实际班组及最近真实到货，允许的最近到货年龄为 `max(180,单程×2+30)` 秒，不拿过去累计运输次数冒充当前供货。之后由事件登记chartered，不奖励人口或库存。

首城要求连续300秒满足：

1. 本地至少400人，住房未超额；来源、在途、独立邻居都不计入。公共诊疗站/学舍有实际岗位。
2. 本地粮药净供养非负、实际治疗和全部儿童教学通过；无饥饿，健康至少70，Society公共行政正常。
3. 已登记镇制并掌握urbanworks；至少一个邻居 `completedProjects.publicWorks` 已兑现，旧initialAid不算；Regions行政服务正常。
4. 当轮采矿、采煤、冶炼、机械加工都产生了实际输出；生产设施实际用电至少4，烟尘处理设施占用的1电力不算生产用电。
5. 污染低于40；粮食库存至少覆盖本地120秒口粮，工具至少40、铁锭至少40、零件至少20。

当前首城检查没有再次要求当下tradeReady；镇制阶段已要求持续贸易，城市阶段以已经兑现的邻地工程和本地自给为基础。不能把这个差异写成代码仍有“城市必须始终有近期贸易”的额外门槛。

登记后名称固定为“炉火城”，本轮没有自由命名输入。事件显示后如果玩家确认前条件已失效，会提示恢复后再议，不写虚假成功记录。chartered/city是历史获得的状态，供养跌落只重置当前稳定度，不拆房、不清科技、不再领奖。没有城市群成立按钮。

## 9 渐进界面

standards之前不出现“街区”地点；两个邻居之前不出现接纳名册事件。公共设施先可建可配岗，居住街区才依服务条件出现；正式镇制后研究urbanworks，再出现街坊住宅。

“街区”沿用ADR顶栏地点、原生建设按钮、设施计数和短文字，显示本地人数/容量、途中预留、粮药净余量、教学覆盖、当前镇制或城市稳定进度。登记后只有启用/暂停批次接纳的操作，悬停说明成本、往返时间与运力。名册、身份、岗位和继任继续共用已有社会系统，没有新增人口仪表板或开局罗列未来制度。

当前状态行主要说明最新发车/等待原因，没有逐旅队的完整可视化时间表，也没有可操作的逐户亲属名册。这些不影响持久账本，不应把尚无界面的管理能力说成玩家已经可以操作。

正式镇制后，若有至少1名在岗制器工且能实付木10、工具0.5，原有“夜里的冷风”随机事件会由轮值工匠完成维修，只写左侧记录，不再反复弹出相同琐事。未取得镇制、无人值守或材料不足时，仍保留原事件和徒手加固的恢复选项。这不是免费免疫天气，而是已有岗位与材料承担日常公共职责；其他重要条件事件仍保留原生选择窗口。自动维修及缺料回退已有规则回归；自然页面已实际出现轮值工匠维护记录，且首城截图中再次可见；缺料回退仍以规则回归为证。
