# 公用服务与千人城市供养实装

**状态：本轮 Services 与供养接线已实现，规则回归和自然游玩证据分开记录。** 本文说明药物制备、水务、灌溉、密集住区、街区学校，以及地方长期岗位分配。百年测试中的1000人是明确的合成初始名册，不是浏览器已自然发展到1000人；也不代表三城3000人、铁路、国家或地球统一已经完成。

材料与同一轮电力的基础规则见设计20，货运与共同施工见设计21，来源自身扩班见设计22。本文件不另建人口、库存或电力账。

## 1 前置与设施

药物制备 medicine 要求 sanitation、chemistry、曾取得 home 首城资格，并且仓库已有化学品。研究支付化学品12、玻璃8、知识80，360秒。公用工程 municipal_engineering 要求 urbanworks、steel、chemistry、曾取得首城且已有钢和玻璃，支付钢20、玻璃12、零件12、知识100，420秒。均不要求当前仍有400人，更不要求先达到1000或3000。

| 设施 | 前置 | 实际材料成本 | 工期 / 每节点上限 | 完工后的能力 |
| --- | --- | --- | --- | --- |
| 药物制备所 pharmacy | medicine | 木180、铁40、玻璃10、零件12、工具12 | 240秒 / 8座 | 每座8药剂师岗位 |
| 公共水务站 waterworks | municipal_engineering | 木240、钢40、玻璃12、零件20、工具16 | 300秒 / 4座 | 每座最多8水务岗位，按电动或手动模式值守 |
| 水务田片 waterfield | municipal_engineering | 木160、铁12、工具18 | 180秒 / 10座 | 每座8农作岗位 |
| 田片灌溉改造 irrigationworks | municipal_engineering，已有水务田片 | 木180、钢12、玻璃4、零件8、工具20 | 240秒 / 1项 | 仅使水务田片能按实际供水取得较高产率 |
| 街区学校 districtschool | municipal_engineering | 木200、钢16、玻璃12、零件8、工具12 | 240秒 / 4座 | 每座12教师岗位 |
| 密集住区 densehousing | municipal_engineering，公共服务及供水满足 | 木300、钢90、玻璃40、零件30、工具20 | 360秒 / 6座 | 每座160床 |

已有诊所、学舍、农田与住宅的成本、岗位和配方不因研究完成而免费升级。上述能力只有对应工程完工才加入；建设学校不赠教师，增加床位不赠居民。

## 2 Home 付款与地方运输使用同一套工程规则

Services 状态放在 `c.services.nodes.home/river/rail/highland`，只保存已建服务设施、当前项目、完工记录、手动水务设置与供水证据。Home 人口和仓库仍归原 Society/State，地方人口、仓库和岗位仍唯一归 Regions，旅客与预留床位仍归 Urban。

Home 开工时一次支付全套材料；两名在原生岗位表分派的营建工才推进工期。缺成年人、健康不足或没有在岗建设者时暂停，不从未成年名册补成人。完成后营建工岗位自动释放，其他新岗位仍需玩家分派。

地方工程先进入 supplying。材料从炉火城实际装车，占既有路线和容量，到达后进入项目 buffer；不得借用地方库存当作已经收货。足额时一次消耗全套材料，转入 building，由两名当地成年建设者施工。地方接纳资格、健康或劳动力变化会暂停，不退还已消耗材料，不赠送替补工人。地方的公用工程、市政工程、旧公共项目和货车改装共享建设者，不能同时让同两人完成多项施工。

每项工程保存递增编号与收货回执。有效收货必须对应在途队列中的同一货物对象、正确项目编号、方向、状态和到达时间；复制货单或重复回调不能再次入库。未交付的材料可按既有道路规则返航，已交付材料留在项目账里；完工空车继续返程，即使下一项工程已开始也不丢旧记录。

施工记录有 `lastWorkedAt`：同一模拟秒重复调用、刷新或载入不会多做一秒工。Home 与地方采用同一成本和工期表；地方额外经过真实运输，不能用本地建设按钮瞬间扣掉远方材料。

## 3 公共服务共用节点自己的电力

服务模块没有发电机、没有库存电、没有独立生产计时器。Home 由 Industry 的唯一每10秒结算提供当轮余电，地方由 Municipal 的唯一结算提供该地方余电。服务只消费传入的 `powerAvailable`，通过绑定该节点仓库的付款回调运行，并返回实际 used/demand。

当轮公共服务优先，其内水务先于药物制备；随后才是节点的滤尘、先进材料和普通机械等工序。一个电源不能同时被公共服务和全部工业各用一次，home 的电也不能被地方借走。运行回调的产出已经乘过一次当前产出系数，地方包装层不再重复相乘。

| 服务 | 实际人手与投入 | 当轮结果 |
| --- | --- | --- |
| 电动水务，每站 | 4水务工、4电、化学品0.2、零件0.02 | 600人份供水 |
| 手动水务，每站 | 8水务工、化学品0.2、零件0.02，不用电 | 300人份供水 |
| 药物制备，每药剂师 | 食物0.2、化学品0.15、0.5电 | 基础药品0.4，受既有产出系数影响 |

水务按完整值守组运行；只有4人时无法让手动模式伪装成8人。缺电、缺化学品或缺维护件时只运行真正付得起的部分，不把“需求”当成已经兑现的能力。手动水务保留停电后的供水恢复路径；药剂师仍需要电，基础医护的旧配方继续存在。

药剂师和基础医护是两份占用实际成年劳动力的岗位，同一个人不能同时算进两份药品产出。Services 只负责制药，不再扣第二次居民治疗；治疗仍由原节点经济统一支付。城市机械证据使用实际通电机械批次，水务或制药耗电不能充当机械作坊已经运转的证据。

## 4 下一轮供水凭证与农业

水务在模拟时刻 T 真正付出化学品、零件和电力后，保存一张仅供 **T＋10这一轮** 农业使用的凭证：

```js
{ issuedAt:T, usableAt:T+10, validUntil:T+10, capacity, consumed:false }
```

下一次农业结算先调用 `CivilServices.begin(s,id)`。只有时间正好匹配、凭证还没有用过时，才消费它并记录本轮灌溉能力。重复消费、错过指定时刻、换一个节点使用都不会得到水。这里记录的是已经付款的供水服务，不是把上一轮电力存下来再次发电。

当前这一轮的农业产率查询是纯读取：已经消费的水仍可供同一轮工具提示与实际农业一致读取，不会因为新水务运行签发下一张凭证而抹掉本轮结果。预测在克隆中推进到 `nextSettlementAt` 指定的下一结算点，不复用真实状态，也避免同秒幂等保护把下一轮药剂产出误判为零。

水务田片每位农夫原产1.4粮并消耗0.01工具；支付灌溉改造后，只有本轮已兑现供水覆盖实际节点人口时才产2粮，失水则回到1.4。该改造只覆盖新增水务田片，不把地方旧0.8农作、旧1.4田片直接免费变成2粮。Home 已有泵站灌溉等原规则也仍独立生效。

三城预算审计发现 Home 接线最初漏扣新增田片的工具，已统一为按实际可支付的完整岗位结算：仅够0.025工具时，新增田片本轮只有2位农夫产粮并扣0.02，余下岗位等待维护；工具归零不会产出负库存。已有 Home 农田仍按旧配方运行。收入预览只读取、实际结算才扣费，专项回归覆盖干田、供水增产、供水过期及维护不足。

## 5 先维持服务，再扩到千人

密集住区开工需要现有公共诊疗、教学岗位、健康至少60，以及最近实际供水能覆盖“当前人口＋160”。施工过程中仍检查公共服务与供水；断供会停工，恢复后继续已支付的剩余工期。只有完工才增加160床。

每节点最多6座新增960床，但床位不是可立即接纳人数。Home 和目标地方都要继续通过实际粮药、教学、道路、运力和住房预留检查；出生也不能占用已经为在途居民预留的床。新增供水/药剂不会从来源或已经抵达者的历史账里复制人口。

街区学校解决的是原有教师席位随下一代成长而不足的问题。每座真实付费学校新增12个教师岗位，每名在岗教师仍按旧配方消耗0.1木、产0.2知识并照看20名儿童；缺人或教材时，学校建筑本身不算已经完成教育。Home 在原生岗位表手动调配教师；地方仍按真实儿童数除以20向上取整，受已建容量和成年劳动力限制。原地方最多6座学舍的上限没有被免费提高。

## 6 地方长期岗位分配的两项修正

### 出生开支纳入年度粮食预算

只有日常口粮与诊疗食物盈余，仍可能在每年一批新生儿出生时慢慢耗空仓库。Municipal 现用同一 `CivilPopulation` 规则，在克隆的年龄组和出生小数记录上预估下一年可能的出生，计入床位及目标在途床位；不推进真实出生 credit，也不创建孩子。

一个历史年600秒，共60次经济结算。预计出生食物成本除以60，加入每轮农作岗位目标：

`日常口粮＋基础医护食物＋药剂师食物＋贸易出口均摊＋预计出生食物/60＋0.5余量`。

这是岗位规划，不是每10秒再扣一份出生费用。实际年更仍由 Regions 用真实床位、健康、粮食和药品决定出生，成功时仅支付一次每孩6粮与0.2药。若没有足够岗位或成人，预算不会制造产量或强行补发孩子。

### 机械工按维护需求安排

已经进入公用服务或先进材料阶段的地方，不再一直按人口/100扩张机械工并持续把铁转成过量零件。自动目标改为实际小电站、公用电站、水务、滤尘维护需求，加上已承诺零件出口与0.25余量，再按正常通电机械产率倒推；仍保留至少2人的目标，并受地方已付费机械容量及实际成人限制。

这样可为炼钢保留铁料，也能避免随着人口上升出现“零件积满、钢与维护链却慢慢失去原料”的分配失衡。原料、电力不足时实际机械产出仍下降，不能以预算代替真正运行。基础矿、煤、冶炼和制器目标继续按下游投入倒推；缺设施时需要真实扩建，不自动增加容量。

## 7 持久状态与校验

每个 Services 节点保存 buildings、project、completed、nextProject、manualWater、economy、water、irrigation；没有另一份仓库、居民或电池。项目记录 required、buffer、receipts、startedAt、lastWorkedAt 与 remaining。

初始化只接受 services 字段真正缺失的旧档路径，不把显式null/false或损坏数据重新当空档。设施数量必须与逐项完工历史对应，成本与固定配置一致，负库存、重复收货、错误时间、未来水证书、同时占用同两名地方建设者等均拒绝。

完工历史数量上限从设施配置的 max 合计派生，当前为33（原29加4座街区学校），不是随意放开数组上限。四座学校以外的虚增设施或第34项历史同样拒绝。普通读档保留已付款工程、原工期与已消费供水，不重发材料或人口。

核心接口沿用如下：

- `startProject/projectAvailable/facilityGate`：前置、同一建设队占用与实际启动。
- `nextCargo/receiveCargo/validShipment`：地方工程的在途与收货。
- `jobs/capacityBonus/labor`：只由完工设施增加岗位/床位，并按实际成人计运行能力。
- `run(s,id,{factor,run,powerAvailable})`：当轮实际服务，返回 used/demand/waterCapacity/medicine。
- `begin/nextSettlementAt/farmRate`：下一轮供水与纯农业产率查询。
- `tick/validate/refresh/reset`：持久施工、存档校验及原生入口。

## 8 当前证据与边界

Services 专项覆盖真实付款与施工、地方分批运输、库存分离、退休暂停、同秒幂等、供水证书消费/过期、手动供水、部分电力下实际制药、密集住房断供停工、街区学校的实际教师容量以及33项完工历史上限。高级材料、服务、Municipal 和完整 adapter 的集成测试另核对共享电力、资源流量、单次产出系数与机械生产证据。

本轮审计的百年规则实验以**合成1000人年龄名册、有限初始物资与合法付费完工设施**为起点，包含两座付费街区学校。学校完工使该地方从原25名教师容量增加到49名，即最多980名儿童的教学席位，实际教师仍随儿童与成人变化分配。随后连续运行60000模拟秒的真实地方生产、货运、出生、衰老及服务，不在实验中补发人口或库存：

| 指标 | 本次规则实验结果 |
| --- | ---: |
| 初始 / 最终地方人口 | 1000 → 1560 |
| 最低健康 | 100 |
| 最低成年劳动力 | 587 |
| 累计实际出生 | 2204 |
| 教育覆盖证据 | 全程 true |

1560是该河谷完整住房配置的容量，不是额外赠送的人口；2204是百年累计出生，包含后来又离世者，不能加到最终人口上重复统计。实验中的 home 只是有有限预付物资与运输工的固定外部贸易端点，没有宣称同时模拟整个世界的人口百年历史。该结果证明这组设施、名册和岗位策略可以长期供养，不证明所有极端年龄构成、断供、失业或贫仓状态都能自动保持同样结果。

**自然游玩仅记录已观察到的本轮进展：浏览器已经出现材料生产相关内容，河谷达到48床，来源使用自身物资进行了扩班。** 最新资源量、人口、时间、领袖、截图和原样档路径由根代理在设计08/10更新；本文不另填未经确认的数值，不把上述合成1000→1560实验写成自然扩城成绩。

千人公共服务已经有实际可运行的设施与资源路径；多城3000、骨干铁路、跨城电网、共同财政和建国仍需后续独立施工、物流与自然验证，当前不以空按钮或一次授名事件替代。
